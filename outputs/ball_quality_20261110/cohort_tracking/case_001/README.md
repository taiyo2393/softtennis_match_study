# 固定標本001への既存選手追跡処理の適用

時刻順で固定した最初の30候補群のうち、未処理の先頭001を処理した。既存の人手得点側「手前」を再利用した。処理後の見栄えでの候補選択、パラメータ調整、モデル追加学習はしていない。

YOLO11m＋ByteTrackの全画面人物検出、既存の奥側画像拡大検出、手前の時間的初期化・再取得・サイズ基準更新、奥ペアの短い途切れを考慮したオフライン経路探索を、そのまま新しい出力先で実行した。初期化はF7。新たな座標補間はない。

過去の接触記録1.450950秒を既存規則でF87へ整数化し、F117〜177の2フレーム間隔31時点を入力にした。**31/31時点に4人分の候補がある。これは可用性であり、本人同定・位置精度100%ではない。** 既存接触時刻の精度も新たに確定していない。

元候補の文脈F0〜599も追跡したが、この600フレームはプレー前後を含みうる範囲。4枠がある542/600という値をラリー全体の追跡成功率として使わない。F599には次の映像へのディゾルブが見え、スコア表示も進んでいる。これは場面転換まで機械的に処理した例であり、得点成立時刻ではない。今回の入力はF177までなので、この終盤画像は配置特徴に使っていない。

AIが `candidate_sequence_grid.jpg` と `far_pair_detail_grid.jpg` のF7・87・117・147・177・237・357・477・599を点検した。指定窓の3時点F117・147・177では4つの枠が4選手を指し、点検列で明らかなF1/F2の逆転は見られない。これは疎な画像のAI所見で、全フレームの独立本人確認ではない。サーブ後の相手側の応答とその後のプレーが見え、固定入力が序盤プレーに含まれるという解釈を支持する。

`four_player_path.csv` が今回の結合結果。手前はadaptive_near、奥はoffline_short_gap_far。`tracking_quality_20261102_stage4/.../selected_four.csv` は中間出力で、最終的な奥側経路とは異なる。見栄えのよい中間結果への差し替えはしていない。

`verification.json` で、全2321選手観測の元の拡大・全画面検出枠との座標完全一致、一時点での一人一枠・同一raw IDの二重割当てなし、固定窓の379値の別実装再計算一致、動画2本1200フレームの全デコード、旧ソース・重み・参照ハッシュの保持を確認した。これらの検査は出力整合性を示し、追跡精度を測る独立正解を追加するものではない。

今回の結果は既存8候補と別に保存し、`current9_player_inputs` で比較用入力へ結合した。新しい人手確認は依頼していない。
