# 11候補の比較用入力（006追加）

006を追加し、既存の人手得点側11候補すべてに選手配置の候補入力を対応づけた。手前得点7・奥得点4。ラベル表は既存の最新回答を再利用し、025の手前への訂正も保持した。11件すべての独立な追跡精度を検証したという意味ではない。

固定した最初の30候補群内では8件の入力作成、未処理22件。044・048・056は補助開発例として別に数えている。次の候補は008。

## 006で分かった限界

指定窓F10536〜10596の31時点中、4人分の観測は後半11時点。前半20時点は4人同時の初期化を待つため全スロットが空欄だった。その間も、後に手前2人へ割り当てたraw IDの検出は全20時点に存在する。映像に選手がいないこととは区別する。

指定した末尾時点の1時点版は4人分がある。区間平均は後半の11時点だけを使い、両ペア観測率11/31を付けた。完全な1秒軌跡の平均とは呼ばず、欠測やその原因を一緒に評価する。1時点版と区間版で使える情報量が異なる具体例でもある。

006の元画像列はサーブに続くプレーと整合した。最終経路の長い途切れ6箇所もAIが点検し、点検列では明らかな相方との交換は見られなかった。ただし、遮蔽や画面端では部分枠が混じる。本人対応の整合性と、位置の代理値の正確さは別問題。詳細は `cohort_tracking/case_006/README.md`。

## 比較用ファイル

前の10件と同じ列・同じ値を保持し、同じ11候補・同じ順番へそろえた。

- `B1_server_side.csv`: 暫定サーブ側だけ。
- `B2_snapshot.csv`: 同じ基本情報＋指定末尾の配置＋観測フラグ。
- `B2_window_means.csv`: 同じ基本情報＋窓内の利用可能な配置平均＋観測率。
- `diagnostic_snapshot_masks_only.csv` / `diagnostic_window_masks_only.csv`: 基本情報と観測の有無だけの診断用。
- `human_outcomes.csv`: 既存の最新人手得点側。入力と分離。
- `rally_metadata.csv`: 入力時刻・群・観測数・由来。
- `fixed30_processing_progress.csv`: 固定名簿を変更しない現在の進捗。

サーブ側は既存のAI候補で、人手正解とは区別する。画像上の概算配置で、コート上の距離や接地点の独立正解ではない。現在は既知の1試合でのデータ構築であり、モデル学習・有効性評価・失点原因の推定はしていない。球の未整備例を「球なし」で埋めず、球追加の比較も未実施。

`verification.json` と `additional_verification.json` は前10件の入力保持、候補順・入力列、初期化待ちの欠測、006の末尾観測と区間観測率、元ラベル全11件との一致、旧成果物の保持の検査。独立の追跡精度評価ではない。
