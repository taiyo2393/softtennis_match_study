前日に作った8候補のうち、終端候補との前後関係をまだ整理していなかった6候補を点検した。**6候補とも、固定入力窓がサーブに続くプレー中にあるという解釈と整合した。明らかな待機・やり直し・終了後の混入は、点検画像では見つからなかった。** これで開始・終了の人手正解が6件増えたとは扱わない。

## 確認方法と範囲

旧編集版の元動画 `data/raw/match1.mp4` を使用し、4K・59.94fpsの元source frame番号で切り出した。動画全体のSHA-256は前日の処理と同じ `547e5cfd2ed6b0693a83201b1241ba6eb93ab7be8f3f2b135dee2cc48f94258d`。再ダウンロード版との混同や一律オフセット変換はしていない。

サーブ接触候補の先頭約1秒前から、固定入力末尾の約3秒後まで、各候補の全ソースフレームを順番に収録したH.264動画を作成した。全6本・2058フレーム。元の16:9画像を960×540へ縮小し、番号表示は別の上帯へ置いたので画像を縦横に引き伸ばしていない。音声は含まない。

**AIが実際に点検したのは、前後の時間順画像列と、入力窓内の4ソースフレーム間隔16画像、025の追加拡大画像である。** 全フレーム動画を作成したことと、全フレームの動作を人が独立に判定したことを区別する。1秒の入力窓は前日の指定31時点・2フレーム間隔から変更していない。今回の画像点検は4フレーム間隔であり、未点検の中間時点のルール事象を独立に保証しない。

スコア表示は結果ラベルやプレー区分の新たな正解として使わず、サーブ動作後の相手側の応答、選手の打球準備、次の応答が窓の後も続くことを根拠にした。既存の人手得点側は保持した。

`eight_candidate_phase_evidence.csv` は、前日の8候補の固定入力範囲・人手得点側と、今回のプレー区分の根拠を別表で結び直したもの。新しく点検した6候補は `ai_visual_sequence_supported`、044・056は既存の有効サーブ・終端候補範囲に基づく状態を保持した。既存2候補のサーブ有効性は人手確認済み、他の6候補の確認状況は変更しない。

この表は解析の入力列に使うものではない。元の特徴量、得点側、候補の開始・終了、正規追跡参照、学習区分は書き換えていない。025の先頭4時点が出力開始前という欠測も、そのまま残る。人手の確認表を無視して「分析適格ゼロ」とする運用や、AIの所見を人手の正解へ昇格させる運用はしない。

研究上は、**8候補の配置特徴を探索的に整えるための序盤範囲が、既存2例の事象範囲と新規6例のAI画像点検で支持された**段階である。8候補・1試合による便宜標本で、得点側の予測性能・配置の優劣・失点原因の結論は出さない。追跡の可用性、本人同定、位置誤差はそれぞれ別の問題として残る。

次の優先事項は、観測しやすい時点へ窓を動かすことではなく、欠測を含む固定入力を維持し、サーブ側などの基礎条件と配置情報を比べられる標本計画を決めること。打法の違いも開始候補の取りこぼし要因として扱う。

## 証拠と整合性検査
