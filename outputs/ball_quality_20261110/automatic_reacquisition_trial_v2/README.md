# 通常追跡経路からの誤ったID変更を再現

011でN2が相手選手へ移る失敗を、同じ検出枠・同じ外観特徴・同じ処理で再現した。対照は、既存の手前ID変更がある002・003・025と、IDが安定している005。全5区間を変更案の結果を見る前に固定し、元の割り当て・由来・丸めたコスト・代替候補との差を完全再現できたことを確認した。元データを正解と見なした評価ではなく、比較条件の検査である。

011ではF27223でraw1から部分枠raw1000268へ、F27231でraw409へ移る。いずれも `continuous_assignment` として採用され、8フレームの再取得確認を通っていない。F27231のコストは0.841924、代替候補との差は0.208076で、既存の通常割り当て条件を通過した。N2の外観ギャラリーとの距離0.543999に対して初期の相手への距離は0.502068だが、この距離差を本人同定確率と読まない。元の非選手用の除外対象には、初期の相手2人の外観は含まれていない。

数値閾値を探索せず、次の2案を比較した。

- B：手前の新しい検出IDを通常継続経路から採用せず、既存の再取得確認経路へ回す。
- C：Bに加え、初期の相手2人の外観を手前選手の除外対象へ追加する。

011で以前確認した取り違え時点では、両案ともN2は元のサーバーraw1を指し、raw409へ移る出力はなくなった。一方、003の正しいID変更後44フレームを出力できなくなったため、両案の正規採用は見送った。002の再取得は7フレーム遅れ、025では画面端の1フレームだけの候補を失った。005は同じ手前割り当てを保持した。B/Cの手前出力はこの5区間では同じで、相手外観の追加による独立した改善は示せていない。

`control_image_review` には全4変更の元出力とCの画像列を保存した。AI点検では002・003・025の継続して観測できる変更は同じ選手と整合し、025のもう一つは画面端の1フレームだけで、その後は元処理にも観測がない。これは独立した人手正解ではない。

この結果を見てから設計した追加案は `../automatic_reacquisition_followup`。追加案を事前登録した独立検証と呼ばない。012など未処理候補はまだ見ていない。今回、正規の追跡・15候補の配置入力・得点側ラベルは更新していない。

最初の試行 `../automatic_reacquisition_trial` は、CSVの数値文字列と計算値の型をそのまま比較した照合処理の問題で停止した。コードと停止記録を残し、v2では比較表現を揃えた。v2では5区間全ての元出力を完全再現した。
