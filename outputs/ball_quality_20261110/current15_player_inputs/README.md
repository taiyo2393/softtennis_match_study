# 配置入力15候補：011はAI指定の修正版

011の別保存した修正版を追加し、15候補の配置入力を作成した。固定30候補群内では12件作成・18件未処理。次の未処理候補は012。得点側の人手確認は11件（手前7・奥4）のまま、008〜011の4件は未確認。15件を正解付きの分析適格ラリーや、自動追跡の成功数と数えない。

011はサーブの再試技を区別し、接触候補F26897〜26903を追跡前にAIが固定。指定窓F26933〜26993の31時点に4枠があり、全31画像では同じ4人に対応して見える。一方、その後にN2が奥の橙色の選手を追うため元の全区間自動出力は不採用とした。AIが実際のサーバーの元検出IDを指定し、N1を保持、奥側を同じ設定で再探索した個別修正版を今回の由来とした。元検出がない18フレームは欠測のまま。

修正前後で指定序盤の124個の枠・元ID・スロットの対応と3種類の特徴CSVは同一。序盤の出力だけでは後の取り違えを判別できなかった。数値検査と点検画像で個別修正を確認したが、独立した本人同定・位置精度や、自動再取得の根本解決は未達。

`B1_server_side.csv`、`B2_snapshot.csv`、`B2_window_means.csv`、欠測だけの診断2ファイルは同じ15行・同じ順序。旧14件の値、009のAI指定、確認済み11ラベル、以前のスコア検証標本は保持した。`processing_interventions.csv` と `rally_metadata.csv` に011の修正版の由来を記録。

`human_outcomes.csv` は未確認を含む台帳、`confirmed_human_outcomes.csv` は既存の確認済み11件だけ。未確認の勝者を機械のスコア候補で埋めない。サーブ側も原画像に基づくAI候補で、人手正解ではない。

人物対応には後続フレームを使う処理を含む。序盤時点の得点予測を評価する前には、入力末尾までの映像で再追跡する必要がある。今回、学習・性能推定・球追加の比較はしていない。検査合格はデータ対応・計算・保存の整合性を示し、追跡精度や研究の有効性を証明するものではない。
