# 015：固定ガードでも初期化の審判混入は直らない

014の時点で固定したコード・閾値・8フレーム確認長を変更せず、同じ検出枠・外観特徴で従来処理を完全再現して比較した。個別人物ID指定はこの比較に追加していない。

**両自動処理とも4選手追跡として不採用。** 初期化時にN1として右端の審判raw1を選び、全31指定時点F38846〜38906でその誤割当を保持した。実選手raw3は検出されている。候補4枠が31/31時点で存在し、序盤配置値が従来と同じでも、正しい4選手追跡の確認にはならない。

全区間では元の手前1306観測に対し試作1281観測、25観測を見送る。手前の検出ID変更回数は5→3だが、審判の経路で発生する変更であり、実選手の入れ替わりを防いだ改善とは数えない。初期化の誤人物選択を、再取得確認だけで直す仕組みではなかった。

元枠・配置値379個の再計算・660動画フレームの復号・コードと入力ハッシュの整合性は検査した。`status=passed` はこの整合性検査の合格であり、本人同定の正しさではない。人物対応の不採用理由は `AI_visual_findings.json` に明記した。

AIが実選手raw3を個別指定した修正版は `../cohort_tracking/case_015/AI_native_binding` に別保存する。自動試作の出力やスコアには混ぜず、配置入力側にもAI介入の由来を残す。修正版にも独立した精度評価はない。

既存接触時刻の時間精度、サービス有効性、正式な終端、得点側の新たな人手確認は行っていない。確認済み11ラベルと固定16件の得点検証標本を保持。今回も学習・得点側性能推定・球追加比較・正規処理の置換は行わない。

次の優先事項は初期の人物選択で審判等を除外する対策。次の未処理016は順序を保持する。今回を用いて対策を作った場合は開発事例とし、その後の区間で別途条件を固定して比較する。
