# 配置入力14候補：010を追加

固定順の010を追加し、14候補の配置入力を作成した。固定30候補群内は11件作成、19件未処理、次は011。人手確認済みの得点側は11件（手前7・奥4）のまま、008・009・010は未確認。14件を「正解付きの分析適格ラリー」と数えない。

010はAIが原画像からサーブ接触候補F23690〜23698を追跡前に固定し、F23728〜23788の31要求時点を処理した。27時点に4人の候補があり、欠けた4時点にも元の人物検出は存在する。初期選手以外の外観に近い候補を除外する条件で落ちたことを再現した。比較条件を保ち、閾値・指定時刻・欠測を変更していない。AIによる人物ID差し替えは今回加えていないが、接触候補と人物対応の点検はAIによるもので、独立の人手正解ではない。

`B1_server_side.csv`、`B2_snapshot.csv`、`B2_window_means.csv` と欠測だけの診断2ファイルは同じ14行、同じ順序。旧13件は全て同じ値を保持した。009のAI指定による修正版の由来も `processing_interventions.csv` と `rally_metadata.csv` に保持している。

`human_outcomes.csv` は未確認行を含む結果台帳、`confirmed_human_outcomes.csv` は既存の人手確認11件だけ。将来の教師あり評価では確認済みファイルだけを結合し、未確認を機械スコアの候補で埋めない。サーブ側は原画像に基づくAI候補であり、勝者から逆算していない。

**現状の追跡は後続フレームを使うオフライン処理を含む。** 序盤の位置だけを入力列にしても、人物対応に未来情報を使わなかったことにはならない。序盤時点の予測性能を評価する前に、入力末尾までだけの映像で追跡を再実行する必要がある。今回モデル学習・性能推定・球追加の比較は行っていない。

数値・対応・保持の検査は `verification.json` と `additional_verification.json`。これらの合格は追跡精度や有効性の証明ではない。同一試合の開発例である制約も変わらない。
