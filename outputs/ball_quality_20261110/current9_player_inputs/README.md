# 9候補の比較用入力（2026-11-10）

固定した時刻順の最初の未処理候補001を、既存の人物検出・再取得・奥ペアの経路探索処理で追加した。既存8候補の出力は保持し、合計9候補（人手得点側：手前6・奥3）を同じ入力形式で結合した。人物追跡や予測の精度が検証された9件という意味ではない。

001の固定入力F117〜177は31要求時点すべてに4人分の候補があった。元の検出枠との対応と特徴計算を検査し、指定窓内を含む時間順画像でもAIが点検した。詳細は隣の `cohort_tracking/case_001/README.md`。

## 比較を実行できるデータ構造

|ファイル|得点側を除く入力列数|内容|
|---|---:|---|
|B1_server_side.csv|1|暫定サーブ側|
|B2_snapshot.csv|11|同じサーブ側＋指定窓末尾の配置8特徴＋ペア観測フラグ2|
|B2_window_means.csv|11|同じサーブ側＋指定窓内の配置平均8特徴＋ペア観測率2|
|diagnostic_snapshot_masks_only.csv|3|サーブ側＋1時点版の観測フラグだけ|
|diagnostic_window_masks_only.csv|3|サーブ側＋区間版の観測率だけ|

全ファイルは同じ9候補・同じ順番。rally_candidate_idは結合キーで、モデル入力ではない。勝者・絶対時刻・終端・ファイルパス・群IDを入力へ入れていない。欠測座標は空欄を保持した。人手得点側は `human_outcomes.csv` に分離してある。

サーブ側は既存のAIによる暫定属性で、人手の独立確認済みではない。得点前のスコア、サーブの試行番号、チーム等の重要な基礎条件はまだ十分そろっていない。これだけでサーブや選手の影響を調整できたとは扱わない。画像正規化配置であり、コート上の距離や接地位置の正解でもない。

区間版は検証前の比較条件として、8つの平均と2つの観測率に絞った。元のより多い要約特徴も `source_window_summary_features.csv` に保存するが、成績を見て入力を選んだわけではない。欠測処理や正規化を将来行う場合は、学習側でだけ決める。

**モデルは学習しておらず、得点側の予測性能や配置の有効性の数値は出していない。** 9件・1試合での性能比較は不安定で、過去の多数の開発に使用した映像でもある。球の整備済み例2件は両方手前得点のため、9件の欠測を「球なし」で埋めるなどしてB3を作っていない。
