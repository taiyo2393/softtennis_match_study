# match2 スコア表示の確認用一覧

`scan_match2_scoreboard.py` は動画左上のスコア表示を時刻順に抽出し、人が読み取る一覧を作ります。OCR・機械学習・得点者推定は行いません。**安定区間は「似た画面が続いた候補」であり、その数はポイント数ではありません。** この段階では全点の数やラリーの開始・終了は未確定です。

## 実行

```powershell
& 'C:\Users\ta239\AppData\Local\Programs\Python\Python312\python.exe' -u 'outputs/match2_point_inventory_20261117/scan_match2_scoreboard.py'
```

入力と出力の既定パスはスクリプトの位置を基準に解決するので、作業ディレクトリに依存しません。動画は読み取り専用で扱います。既存の実行結果や記入済みテンプレートがある出力先には上書きしません。再実行するときは別の `--output-dir` を指定してください。

```powershell

```

主な引数:

| 引数 | 既定値・意味 |
| --- | --- |
| `--video` | `study/data/raw/match2.mp4` |
| `--output-dir` | スクリプトと同じフォルダ |
| `--step` | 15 フレーム。約 0.25025 秒ごとにサンプリング |
| `--crop X1 Y1 X2 Y2` | 実フレームのピクセル座標、右端・下端は含まない。省略時は `(0,0,round(幅/3),round(高さ*150/1080))`。3840×2160 では `(0,0,1280,300)` |
| `--analysis-width` | 320。縦横比を維持した縮小グレースケールで差分を測定 |
| `--change-threshold` | 省略時は全サンプルの差分分布から自動設定 |
| `--merge-threshold` | 省略時は差分分布と有効な change 閾値から自動設定 |
| `--min-stable-sec` | 1.5 秒。これ未満の安定 run を破棄 |

## 処理と区間の定義

1. 先頭 F0 から `grab()` で全フレームを順次進み、F0, F15, F30, … だけ `retrieve()` します。各 crop をグレースケール・幅 320 に縮小し、直前サンプルとの画素ごとの平均絶対差と平均輝度を記録します。差分と輝度の単位は 0〜255 です。
2. `diff[i] < change_threshold` は前後のサンプル i−1 と i を結びます。閾値以上ならその間で切ります。連結したサンプルの最初と最後の時刻差が 1.5 秒以上の run だけを残します。最終 run も判定します。先頭サンプルの diff は便宜上 0 とし、閾値計算から除きます。
3. 短い run を除いた後、時刻順に隣接する安定区間の代表画像を比較します。差が merge 閾値未満、かつ結合中の先頭 run の固定代表画像との差も同じ閾値未満なら結合します。固定代表との比較は小さな変化の連鎖による過剰結合を抑えるためです。gap の長さには上限を設けません。結合の可否と実際の差分は `metadata.json` の `merge_log` に記録します。
4. 代表は区間中央に最も近い安定サンプルです。同距離では早い方を選びます。結合区間の中央が不安定な gap にあれば、残った安定部分のうち最も近いサンプルを選びます。動画をもう一度先頭から `grab()/retrieve()` で順次読み、これらの代表だけを元解像度で保存します。動画へのシークはどちらのパスでも行いません。

開始・終了フレームはともに **0 始まりの観測サンプルを含む端点**です。`duration_sec = (end_frame - start_frame) / fps` とし、サンプル間の変化時刻を補間・外挿しません。結合した区間の長さには不安定な gap が含まれます。`segment_stable_spans` に元の安定部分を残すので、必要に応じて結合履歴を確認できます。CSV の `mean_brightness` は代表画像を解析用に縮小したときの平均輝度です。

自動閾値は初期設定用のヒューリスティックです。全試合に対する検出精度は未検証です。q25、q50、q75 をそれぞれ差分の 25、50、75 パーセンタイル、IQR = q75−q25 として、次を使用します。

```text
change = max(0.25, min(12.0, q50 + 1.5 * IQR))
merge  = max(0.05, min(有効な change * 0.5, q50 + 0.5 * IQR))
```

各引数が指定された場合はその値を使用します。分布の中央値、分位点、式、自動値、有効値、引数による上書きの有無は metadata に記録します。表示領域内の動く背景、微小な数字の変化、ゆっくりした変化、フェードなどは誤分割や見逃しの原因になります。同じ表示への復帰も画像の類似だけでは保証できないので、結合区間内の短い別スコア表示は原動画で確認してください。

## 出力の見方

| ファイル | 内容 |
| --- | --- |
| `samples.csv` | `frame, time_sec, diff, mean_brightness`。全サンプルの差分・輝度。安定区間に採用されなかった部分も残る |
| `stable_segments.csv` | `segment_id, start_frame, end_frame, start_sec, end_sec, duration_sec, rep_frame, mean_brightness`。結合後の区間を時刻順に掲載 |
| `crops/segment_XXXX.png` または `.jpg` | 代表の元解像度 crop。PNG 圧縮9を試し、100,000 bytes を超えた場合は JPEG 品質90。縮小しない。内容次第で約100KBを超える場合があり、実サイズ・形式を metadata に記録 |
| `review_sheets/sheet_XX.jpg` | 1枚24区間、最後だけ端数。左に segment_id、代表時刻 `mm:ss.s`、代表フレーム、開始時刻。右に crop 全体を縦横比を保って配置。実バイト数を確認し、500,000 bytes 未満になるよう品質・必要なら一覧のみの寸法を調整 |
| `score_transcription_template.csv` | 読み取り結果を記入する UTF-8 BOM 付き CSV。`segment_id, start_sec, rep_frame` 以外は空欄 |
| `metadata.json` | 入力動画、実測 fps・実フレーム寸法、ヘッダー/読込フレーム数、crop、step、閾値、処理時間、OpenCV バージョン、安定サンプルの割合、結合履歴、画像サイズ、警告 |
| `README.md` | この説明 |

数字が潰れる場合は該当する `crops/` を直接開きます。一覧は読み取りやすさを保証するものではなく、判読不能を推測で埋めないでください。スコアが見えない画面も候補に含まれます。安定区間が0件なら CSV はヘッダーだけ、画像フォルダは空になり、metadata と標準出力で警告します。

処理の途中では縮小グレースケールを一時ファイルに保持します。既定値・指定動画では約292MBの一時容量が必要で、正常終了時・通常の例外終了時に削除します。元解像度 crop の全サンプル分は保存しません。強制終了で `.scoreboard_cache_*` が残ることがあります。中断・失敗後は別の出力フォルダでやり直し、`metadata.json` の `status: complete` を完了の目印にします。ヘッダーのフレーム数と実読込数が異なる場合は途中までを全試合として扱わず、エラー終了します。

## 書き起こしと全点の確定

1. 一覧と元解像度 crop を読んで `score_transcription_template.csv` を埋めます。`is_scoreboard_visible` は `1`（必要なスコアが読める）、`0`（非表示・判読不能）を基本とし、一部だけ読める場合やリプレイ、結合の疑いは `note` に書きます。見えない数字は空欄のままにします。
2. `near` は手前側、`far` は奥側の選手側として、原動画で表示の名前・行と選手を対応付けます。画面上段＝near と仮定しません。チェンジサイズ後は対応を確認し直し、チームの識別情報を `note` に残します。表示と側の対応が不明な場合は未確定と記録します。
3. 時刻順のスコア列を照合し、同一スコアの重複候補、見えない区間、リプレイ中の過去の表示、ゲーム更新・リセットを確認します。`stable_sample_fraction_before_merging` が低い場合や区間間に大きな空白がある場合は、その時間帯を `samples.csv` と原動画で確認します。冒頭 F0〜最初の区間、末尾の区間〜動画終了も確認対象です。表示変化数をそのまま全ポイント数にしません。
4. 各得点更新の前後を原動画で読み、独立したポイントIDと更新前後スコアを確定します。スコア更新はプレー終了より遅れ、次のサーブとも一致しません。**各点のプレー区間を確定するには原動画で開始・終了を確認する必要があります。** 開始を最初のサーブ動作／打球のどちらにするか、終了を最終打球／失点確定のどちらにするかを統一し、フレーム番号と根拠を別のポイント台帳に記録します。レット・フォルト・編集・欠落がある場合も記録してください。
5. 全点数をスコアの推移と照合し、未確認区間を残したまま「全点確定」としないでください。本スクリプトが出力するのは確認材料までです。

区間が細切れになる場合は crop に動く背景が入りすぎていないかを先に確認します。その上で change 閾値を上げると分割が減り、下げると小さな変化を拾いやすくなります。異なる得点が一つにまとまる場合は change・merge 閾値を下げる、または step を小さくして再確認します。閾値を上げると得点変化の見逃しが増え得ます。設定ごとに別出力先を使用し、既知箇所だけに合うよう過度に調整しないでください。

## 検証（実行後に行う）

以下は既存作業で確認済みのサーブ打球付近です。境界の正解ラベルではなく、区間検出が点の整理に使えるかを確認する目印にします。

| --- | --- | --- |
| 第1点 | F12326 | 03:25.6 |
| 第4点 | F16704 | 04:38.7 |
| 第5点 | F18712 | 05:12.2 |
| 第6点 | F20781 | 05:46.7 |

1. `metadata.json` の `status`、読込フレーム数（想定182506）、fps（想定60000/1001 ≈59.94006）、crop（4K既定1280×300）を確認します。全一覧画像が500,000 bytes未満か、画像記録と実ファイルの両方で確認します。
2. 各サーブの前後、まず20秒程度を原動画で見て、実際にスコア表示が変わる時刻を確認します。前のポイント後の更新などが範囲外なら広げます。その付近の `stable_segments.csv` の端点と一覧を照合し、表示更新の前後が別区間として残っているかを確認します。サーブフレームそのものを境界として要求しません。
3. 例として、下記で第4点付近の候補を抽出できます。

```powershell
Import-Csv 'outputs/match2_point_inventory_20261117/stable_segments.csv' | Where-Object { [double]$_.start_sec -le 299 -and [double]$_.end_sec -ge 258 } | Format-Table
```

4. 境界がない場合は `samples.csv` の該当時刻の diff と閾値を比較し、`merge_log` と `segment_stable_spans` で結合によって消えたのか、安定 run が短くて落ちたのか、最初から検出されなかったのかを確認します。単独の急な変化を正しく分割できた場合、サンプリングによる時間刻みは約0.25秒です。フェード、不安定区間、短い run の破棄、結合によって、CSV の端点と実際の表示更新時刻はさらに離れることがあります。1.5秒未満の表示は安定候補にならず、全ての瞬間的な変化を保証する設計ではありません。
5. 上記以外のゲーム途中・ゲーム境界・リプレイ・動画末尾でも同様に確認し、見逃しと過分割を記録します。既知4箇所だけの一致では全試合に対する完全性の証拠になりません。

## 処理時間の目安

4K動画の逐次デコードをおおむね2回行います。`grab()` でもコーデックによっては各フレームのデコードが必要なので、15フレーム間隔にしても処理時間が1/15になるわけではありません。合計約365,000フレームを30〜150フレーム/秒で進める場合、画像作成を除いて約40分〜3.5時間です。これは実測値ではなく速度を仮定した換算であり、CPU・コーデック・ディスクによってはさらに時間がかかります。標準出力に各パス10,000フレームごとの実測速度・そのパスの残り時間を表示します。最初の10,000フレームの速度から、2パスの所要時間を見積もってください。

作成時には Python 起動・動画処理・出力画像の確認を行っていません。文法と処理の対応は目視レビューのみです。初回実行後に上記の検証を行ってください。
