# 時系列と画面切り替えによる誤検出の保留

**2026-11-03の安全性点検：時系列だけによる全区間への自動除外は採用しない。**
002・318で本物の球を誤って保留したことがユーザー確認された。
詳細と補正レイヤーは `suppression_audit_20261103/README.md` を参照。
以下は指摘済み018の3点を改善した先行実験の記録であり、一般的な追跡品質の保証ではない。

ユーザーが018の208・229・230フレームで指摘した手への誤検出に対応した実験版。
前の白手袋対策はフレームごとの姿勢・服色の判定が中心であり、軌跡の整合性を確認していなかった。
今回の映像出力は、既存の白手袋対策の後に、前後の軌跡と画面切り替えの判定を適用する。

## 指摘された3フレーム

| フレーム | 元の検出位置 | 新しい扱い | 根拠 |
|---|---|---|---|
| 208 | (1119,555) | 保留 | 前後の10点が支持する軌跡から約368px離れる。支持点は前8点・後2点。別の連続軌跡としても支持されない。 |
| 229 | (1115,558) | 保留 | 別のカメラ映像へ移る途中。旧映像の座標系で軌跡をつながない。 |
| 230 | (1117,556) | 保留 | 同じ画面切り替え区間。 |

同じ手に移っていた204も約363pxの逸脱として保留した。
018では画像変化から223–239を切り替えの不確実区間とした。個別のフレーム番号を除外ルールへ埋め込んだ処理ではない。
219・220の元の検出座標は保持している。
013・018の元の座標・注釈・先行実験の結果は変更していない。

## 時系列の判定

- 対象時刻の前後30フレーム（約0.5秒ずつ）の検出候補を使う、事後処理である。
- 異なる時刻の点対から局所的な一定速度モデルを作り、16px以内で整合する点を数える。
- 6点以上・12フレーム以上の幅・対象時刻の前後にそれぞれ2点以上の支持がある軌跡を基準にする。
- 基準軌跡から128pxを超えて離れ、別の4点以上の軌跡としても支持されない候補を保留する。
- 打球・バウンドで別の方向へ続く軌跡がある場合は、その枝を残す。速度上限だけで一括除外しない。
- 画像の大域的な変化から切り替え区間を保留し、その前後を同じ座標系として結ばない。
- モデルが予測した位置は判定にだけ使い、欠落箇所の座標として出力しない。

画像変化は縮小画像の12フレーム前との差を使う。平均色差24を超える画素が25%を超えた時刻について、前12・後4フレームを保守的に保留する。
人物の動きやカメラ移動でも反応し得る。編集の始点・終点を高精度に測ったラベルではない。

## 設定選択と評価を分けた記録

`protocol.json` を先に保存し、元の時刻整合済みMS-TrackNetV3を対象に、検証用150標本だけで64/96/128pxと画面保留の有無を比較した。
全設定で位置正解80/121を保持し、誤出力が9件から8件になった。
「同点なら全フレームで保留する出力が少ない方」という選択規則では128px・画面保留なしが選ばれた。
この最小構成を既存テスト150標本に適用した結果は、位置正解96/128・誤出力4件のままで、改善を示さなかった。

一方、試合分析では、カメラが切り替わる間の画像座標を軌跡として扱えない。
そのため、検証標本の正解を失わなかった画面保留ありの構成を、映像分析用の運用候補として `preview_protocol.json` に別途固定した。
さらに018の動画では先行の白手袋対策を合成している。最小構成の集計と、合成後の動画を同一の評価結果として扱わない。

今回の208・229・230は元の150標本に含まれていない。
少数の抜き取り標本が保たれることだけでは、連続軌跡の正しさを確認できないことが示された。
指摘されたフレームは開発の回帰確認であり、新しい独立テストには含めない。

## 動画と検査

- `scene_aware_preview/match1_motion_pilot_018/temporal_review_slow_h264.mp4`：0.25倍速。緑丸は保持した検出、オレンジの×は保留した元の候補。
- 右側の切り出しは640×360の等倍表示で、手と実際の球の周辺を同時に見られる範囲を固定している。
- 両区間の `balltrack_predictions.csv` に全690行を保存した。`raw_*` は元のモデル、`input_*` は先行の白手袋対策を経た入力、通常の座標列は今回の出力。
- `temporal_reason` で軌跡逸脱と画面切り替えを区別する。
- `verification.json`：指摘3点の保留、219・220の保持、raw座標の保存、非保留座標の不変、元注釈の不変を確認した。
- 単発の飛び移りを除外し、支持点のある高速の方向転換を保持する合成データ検査も実施。ただし実映像の全ての打球を保持する証明ではない。
- 出力動画は全960フレームの復号を確認した。復号検査は追跡精度の検査と区別する。

## 限界

指摘と既に見た試合を基に開発した処理であり、汎化性能は未検証。現時点では正式な基準版を置き換えていない。
最大約0.5秒先の情報を使うため、同じ挙動を無遅延のリアルタイム推論には使えない。
複数フレームにわたり一貫して続く誤検出は、別の軌跡として残る場合がある。
前後の支持点が少ない場所では無理に除外しないため、013の435に残る白手袋などは未解決。
姿勢による候補判定と時系列による整合性判定は相互に補う処理で、今回の対策だけで全ての手への誤検出が解消したわけではない。
