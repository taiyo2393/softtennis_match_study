# 時系列による保留の安全性点検（2026-11-03）

時系列多数決だけで候補を自動除外する処理は、全区間に採用しない。
本物のボールを誤って保留した反例が人手で確認されたためである。
指摘済み018の208・229・230を改善できたという個別結果と、処理全体の安全性を分ける。

## 点検対象

固定設定（128px・画面保留なし）の単体処理が20区間で新たに保留した35フレームを全て洗い出した。
検証側17、既使用テスト側18で、既存300標本と重なるのは1フレームだけだった。
残る34フレームの正否は、既存の抜き取り精度に現れない。

全35件を対象時刻±4フレームの生画像でAIが点検した。
手・ラケット・審判付近の候補に加えて、以下の本物の球に見える候補も保留されていた。
この点検は独立した全フレームの正解ラベルの作成ではない。

| 候補 | 観察と確認の範囲 | 現在の扱い |
|---|---|---|
| 002・318 | バウンド中の球。動画でユーザーが「本物のボール」と確認 | 補正レイヤーで元のモデル座標を復元。人手確認として記録 |
| 014・626 | 手元の球に見える。前後の像と明瞭な黄色成分をAIが確認 | 色の手掛かりで元の候補を保護する実験版を作成 |
| 014・630 | 同上 | 同上 |

002・318のユーザー確認は「囲まれた候補が実際の球か」という確認である。
正確な中心画素の注釈は依頼していない。元のモデル座標(558,680)を残し、人手で中心を正確に測った位置とは扱わない。
元の300標本の可視性・座標は変更せず、開発用の追加確認として別保存した。

## 多数決だけでは足りない理由

今回の局所モデルは、検出数の多い軌跡を基準にしている。
その基準が同じ球を追っている保証はなく、別物への繰り返し誤検出が多い場合、本物の球の疎な検出を外れ値として落とせてしまう。
「多数の点が直線に乗ること」と「その直線が対象球の軌跡であること」は別である。
多数点の距離閾値だけを調整してこの反例を通す方法は採らなかった。

次の設計では、基準軌跡が対象球を追っている根拠と、候補の直接的な画像の手掛かりを合わせる必要がある。
軌跡と外観が食い違う場合は不確実として残し、根拠が足りないまま観測を消さない。
手での保持・準備中のバウンド・プレー中・編集区間も区別する必要があるが、現在の全300標本にはその確定区分が揃っていない。

## 外観を使った保護の試作

`../appearance_veto_partial_20261103/` は、候補付近に明瞭な黄色成分がある場合、時系列との不整合だけでは候補を消さない試作。
元の検出座標を戻す処理で、画像から新しい位置を補間して追加する処理ではない。
014・626/630は保護でき、018の208/229/230は保留したままである。
一方、002・318の球像は色が淡く肌色寄りで、固定した黄色範囲では拾えなかった。
服装・照明・ブレに依存する保護であり、これだけで安全性が解決したとは扱わない。

色条件を広げて002・318だけを無理に通す代わりに、この反例を記録し、全区間への自動適用を保留した。
ユーザー確認後の002・318は、アルゴリズムではなく人手確認レイヤーで保護する。
この補正を自動検出精度の向上として集計しない。
