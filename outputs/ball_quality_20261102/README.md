# ボール追跡の改善実験（2026-11-02）

## 判断

弱いヒートマップ候補を短い欠落で復帰する方法は不採用とする。
検証用区間では改善したが、設定を固定したテストでは位置正解数が増えず、誤位置が増えた。
採用版は `../tracking_quality_20261102/ball_aligned/` の時刻整合済み出力を維持する。
`selected_predictions/` は比較実験の出力であり、採用版ではない。

## 方法と比較条件

- 同一試合の既存20区間・300注釈フレームを使用。001–010を設定選択用、011–020をテスト用とした。
- 両方式で同一の注釈・対象フレームを比較。元画像1920×1080における16px以内を位置正解と定義した。
- 既存の強い検出の座標・有無は変更しない。両端に強い検出がある欠落区間に限り、弱いモデル出力を探索した。
- 線形軌道は探索範囲の制限に使用する。出力座標はヒートマップ成分から求め、補間座標を観測として出力しない。
- 欠落上限4/8/12フレーム、ピーク下限0.10/0.15の6設定を比較。探索半径16pxで欠落中の全フレームに候補がある場合に限る。
- 検証用注釈だけで設定を選択し、欠落上限4フレーム・ピーク下限0.15を固定してテストした。テスト結果を見た再調整は行わない。

## 結果

| 指標 | 現行版 | 弱い候補による復帰 |
|---|---:|---:|
| 検証：位置正解数 / ボール可視注釈数 | 80 / 121 | 82 / 121 |
| テスト：位置正解数 / ボール可視注釈数 | 96 / 128 | 96 / 128 |
| テスト：位置再現率（16px以内） | 75.0% | 75.0% |
| テスト：位置正解数 / 座標出力数 | 96 / 100 | 96 / 101 |
| テスト：双方が可視としたフレームの誤位置数（16px超） | 3 | 4 |
| テスト：非可視注釈に対する座標出力数 | 1 | 1 |

テスト10区間全体で座標出力が91フレーム増えたが、その91フレーム全てに正解注釈があるわけではない。
出力の増加を正解数の増加として扱わない。上の結果は注釈された150フレームの比較である。
このテスト区間は過去にも利用した同一試合内の区間であり、新しい独立外部テストではない。
既存注釈の独立性・作成者の確認も未完了であり、数値は暫定比較値として扱う。

## 再現と記録

- `extract_weak_candidates.py`：モデルから欠落フレームの弱い成分を抽出。強い検出との時刻対応も区間ごとに照合。
- `temporal_recovery.py --phase select-validation`：設定選択。
- `temporal_recovery.py --phase evaluate-test`：選択済み設定を固定したテスト。
- `test_recovery.py`：既存検出の保持、ヒートマップに由来する座標、前後アンカー・全欠落フレームの支持・距離・ピーク制約を検査。
- `selection_protocol.json`、`selected_method.json`、`test_results.json`：選択条件と集計値。
- `decision.json`：採否と採用版の参照先。

## 別モデル比較の準備

公式 [TOTNet](https://github.com/AugustRushG/TOTNet) のテニス用重みを、既存環境を変更せず実行できる状態にした。
`totnet_smoke.py` により196個の重みテンソルの厳密な読み込みと、実映像5フレームを使ったCUDA推論を確認した。
重みSHA256・ソースのコミット・入力条件は `totnet_setup_report.json` に保存した。
これは実行確認であり、追跡精度の評価ではない。

重みの設定は5フレーム・対象フレームが末尾（bidirect=False）。学習コードのTennis_Datasetに合わせてBGR入力を使用した。
公開デモにはRGB入力との不一致があり、そのまま流用しない。次の比較では入力条件と座標出力・非可視判定の仕様を先に記録し、
検証用区間で固定してから同一テストへ適用する。位置softmaxのピーク値を、校正された可視確率とは扱わない。
これまで見たテスト区間での改善は開発上の比較に限り、卒論の最終性能主張には別試合などの未使用評価区間が必要となる。

### 比較完了

`totnet_comparison/README.md` に入力条件・比較コードの原点処理修正・設定選択・結果を記録した。
テストの位置正解数は現行版96/128件に対してTOTNet83/128件、位置再現率は75.0%に対して64.8%。
誤位置は3件に対して5件、非可視注釈への誤出力は1件に対して3件となり、TOTNetへの単独置換は不採用。
現行版の未検出時にだけ補う案も検証用標本で採用条件を満たさず、現行版をそのまま保持する設定になった。
これらは同一試合の既存注釈を利用した開発比較であり、外部評価の代わりにはならない。

### 白い手袋への対策：実験版 v1

`glove_guard/README.md` に、青い上着の人物の上げた手首に近い候補を保留する試作を記録した。
検証側で0.12（候補と手首の距離／人物高）に固定し、テストの位置正解96件を維持したまま誤出力を4件から3件へ減らした。
013・018の連続690フレームでは13フレームを保留し、全てのraw座標・非保留行・元ファイルを保持する検査を行った。
この試合の服色に依存し、013の435フレームは姿勢推定の失敗で残る。採用版への置き換えは行っていない。
全300標本の場面区分は既存注記による候補を整理した段階であり、258件を未確定のまま保持する。
可視性と複数球の扱いに確認候補があり、元のラベルを自動変更して精度を再計算していない。

### 時系列・画面切り替えの対策

ユーザーが018の208・229・230で指摘した手への誤検出に対する新版を `temporal_guard/README.md` に記録した。
208は前後の軌跡から約368px離れる未支持の候補、229・230はカメラ切り替え区間として保留した。
動画は先行の白手袋対策と合成し、690行のraw保持と3点の回帰確認を行った。
これら3フレームは元の抽出評価に含まれていなかった。独立した全体精度の改善とは主張せず、元の基準版を保持する。

### 安全性点検（2026-11-03）

`temporal_guard/suppression_audit_20261103/README.md` に全35件の時系列による保留を点検した結果を保存した。
002・318は本物のボールであるとユーザー確認され、時系列の自動除外による反例となった。
同候補は元のモデル座標を人手確認レイヤーで復元した。中心画素の正解注釈やアルゴリズムの精度改善とは区別する。
014・626/630は外観の手掛かりで保護できたが、色だけでは002・318を保護できず、時系列による一括除外は採用しない。

### 複数球への対応（2026-11-03）

基準軌跡を点検すると、002では別の実球、014では線審の頭付近を基準にしていた。
`../ball_quality_20261103/multiball_pilot_002/README.md` に、ヒートマップの複数成分を保持し、2球を別々の初期位置付き追跡候補として出す試作を保存した。
ユーザーの「球が二球ある」という回答は場面の球数の確認とし、全軌跡の精度確認とは扱わない。
観測候補はAが16フレーム、Bが73フレーム。欠落を補間せず、元のモデル・注釈・基準版を保持している。
