# 003のサーブ姿勢による過剰な枠除外を修正（2026-11-02）

## 修正

手前側の初期サイズを固定する代わりに、直近30ソースフレーム分の採用済み観測の
箱高さの中央値で基準を更新する。同じ元ID、短い間隔、移動・サイズ変化が連続し、
他の割り当て選手との強い重なりがない場合だけ更新する。
棄却した枠や欠落・補間値から更新しない。
基準の下限を画像高さの0.16に置くため、最小箱高さは4K画像で172.8pxを下回らない。
初期の腕上げ姿勢の大きい箱から普通の姿勢へ移っても、過剰に小さい枠と判定しにくくした。
この下限は今回の画角用で、別画角へ一般化した基準ではない。

## 003の結果

手前N1の出力は152→408フレーム。欠落していたF4360〜4615の256フレーム（約4.27秒）を
元の検出枠で出力できた。N2も408フレーム。初期化待ち7フレーム以降は手前2枠が続く。
これは候補枠の可用性であり、本人同定精度の数値ではない。

当初、旧奥側経路をそのまま統合すると、003終盤の67フレームで同じ検出枠をN1/F2へ
二重に割り当てることが整合性検査で分かった。旧版ではN1が欠落していたため、
その枠が奥側の候補へ混ざっていた。
003だけは新しい手前位置を使い、奥側を同じ第7段階のアルゴリズム・設定で再計算した。
二重割り当ては最終出力から除去。4枠同時の観測は301/415フレームとなった。
奥側の逆方向照合も開始時の元ID5→F1、元ID3→F2へ戻り、比較607組は全てIoU>=0.5で一致。
これは独立した人手の本人確認ではない。

## 確認済み区間への影響

同じ手前サイズ処理を002・005・007・048にも適用したが、既存の手前の観測枠・元ID・
人物ラベル・座標は全て一致し、追加・削除はなかった。各区間の確認済みの奥側経路は
ファイルをそのまま保持して最終映像へ描画した。これら4区間の出力は変更されていない。
新しい手法の全般的な本人同定精度を測った結果ではない。

## 検証

`test_adaptive_near.py` は、サーブの大きい枠から通常の高さへ連続して変化できること、
急に現れる頭だけの小さい枠を拒否すること、その棄却枠で基準を更新しないことを検査。合格。
最終5動画のフレーム数・H.264/yuv420p・全フレームデコード、全座標と元検出枠の一致、
一人一枠・一枠一人の維持、確認済み4区間の出力一致も確認した。
テスト合格自体は本人対応の人手確認ではない。その後、003の最終動画の提示に対して
ユーザーから「おｋ」と確認された。`players_003_temporal/human_video_review.json`に
提示動画単位の本人対応確認として保存した。独立した全フレーム正解の付与とは扱わない。
025の方向間でのF1/F2反転は、今回の修正対象に含めておらず未解決。
