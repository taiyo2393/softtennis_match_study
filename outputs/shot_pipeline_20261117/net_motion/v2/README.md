## 座標と区間の監査

- build_match2_player_ball_review.pyは追跡中に3840×2160座標でprojectし、CSVではFrameCoordinates.row(to_canonical=False)で1920×1080へ戻す。従ってCSVのbottom_centerを2倍してprotocol.jsonのimage_to_court_homography_canonicalに入力し、同次除算する。build_044_spatiotemporal_pilot.pyのprojectと同じ式。コート座標は正規化x×10.97、y×23.77 m。

- 全17,022行の箱座標でcourt_proxy再現assertを先に実行。許容絶対誤差=1e-10、実際の最大誤差=3.11e-15（正規化座標）。projection_validation.csvにpoint/slot別の誤差を保存。これは既存変換の再現検証で、実位置精度の検証ではない。

- 足首は元画像座標。左右ともconf>=0.3なら中点、片側だけならその足首、両側が低い・座標欠損なら欠測。キャッシュ時間範囲内の未検出・slot欠損を箱で埋めない。キャッシュファイルなし／範囲外だけ箱へfallback。foot_source_mode、foot_source_counts_json、bbox_fallback_frames、ankle_valid_framesに記録する。一つの区間[c-6,end]内で足首とfallback箱が混在すると代理点の差で移動が生じるため、mixed_ankle_bbox_proxyとして判定不能にする。

- 終点=min(次の打球フレーム,c+round(W×fps))。次の打者が前衛でも例外なし。W=0.3/0.4/0.5秒（主0.4）、fps=60000/1001。roundにより主条件は24フレーム、約0.4004秒。ネット通過フレームそのものを測定していないため、論文と厳密に同じ区間ではない。

## 前衛の選択

- 両座標条件とも役割判定にはv1の箱コート位置を使い、足首条件との差を足元へ限定する。非サーブは接触時にネットに近い方、2人の片方でも欠測なら役割不明、距離差<0.5mは曖昧。

- サーブは同じpoint/rallyのlabels次行hitter_slotをレシーバーとして相方を選ぶ。shot_tableとのラベル一致をassert済み。次slotが空欄・不正なら次接触フレームでレシーブ側ベースライン（N:y=0、F:y=23.77）に近い方をレシーバーとする。2人の位置が揃わない・次行がないなら判定不能。距離同率はslot名順。ボールへの近さは使わない。receiver_slot、receiver_basis、role_selection_basisを保存。

## 分類の定数

| 定数 | 値・規則 |
| --- | --- |
| WS / DS | W=0.3/0.4/0.5秒、D=0.2/0.3/0.5m（主W=0.4,D=0.3） |
| ANKLE_CONF | 0.3（以上を採用） |
| MEDIAN_FRAMES / MEAN_FRAMES | 中心中央値5→中心移動平均3 |
| 平滑化端点 | 中央値は3観測以上、移動平均は2観測以上；端は窓を短縮 |
| TURN_DEG / MIN_SEG_FRAMES | 75°以上／各分割区間の時間差4フレーム以上 |
| SEGMENT_DISTANCE_FACTOR | 1.0：分割の両区間の変位>=D（主0.3m） |
| PRE_FRAMES / MIN_PRE | 接触前6フレームの生座標中央値；4観測以上必要 |
| MAX_MISSING / MAX_GAP | 区間欠測20%以下、連続欠測2フレーム以下、両端観測必須 |
| CROSS_DEG / FEINT_MIN,MAX | 8方向の十字軸±10°；誘い候補60〜120° |
| ROLE_MARGIN | 非サーブでネット距離差0.5m未満を曖昧として記録 |
| SHEET_STRIDE / MAX_EXTRA_REVIEW | 6フレーム／変更例を最大10件追加 |

平滑化は[c-6,end]内だけを使い、欠測・追跡segment境界を越えず、欠測時刻を埋めない。前6フレームの始点はv1同様、生座標中央値。最大変位>=Dを動きありとする。再帰分割は条件を満たす角度最大の点（同率は早い方）。分割後の各区間の距離・時間もassert。単の方向は始点→終点、複の評価方向は最終区間。direction3は全体変位、final_direction3は最終区間。局所座標はN=(Δx,Δy)、F=(-Δx,-Δy)で右・ネット方向。前成分>|右成分|を前、-前成分>|右成分|を後ろ、他を横とする。8方向、誘い候補、品質除外・集計スコープはv1と同じ。短い欠測をまたぐ分割ベクトルは観測点同士だけで計算し、経路長は欠測をまたいで加算しない。

## 追記（Claude、2026-11-18）：なぜ精度が上がらないか

- **目視の参照そのものが弱い**：Claude の目視は6フレームおきの縮小画像で付けた。v1 で「動いていない」とした p09_B_01 は、v2 の箱の下端の y が10フレームかけて滑らかに 7.97 m → 8.45 m（約0.5 m 前）へ動いている。一歩踏み出した可能性があり、Claude の「なし」が誤りの可能性がある。井箟ほかの定義では一歩でもモーションになる。
- **足首の位置は奥の選手で不安定**：p09_B_02（奥）では、同じフレームで足首の中点の y が箱の下端より約2.5〜2.7 m 奥に出る。奥のベースライン付近は1画素が約0.3 mに当たるため、数画素の違いが数 mになる。
- **前衛のモーションの大きさ（0.3〜1 m）と、位置の誤差の大きさが同じ程度**である。この精度では、動きの有無や方向を自動で安定して判定できない。
- 次に必要なこと：
  1. 経験者（本人）が、元動画をコマ送りして30件程度の前衛のモーションを付ける。それを参照にして、自動判定との一致を測る（井箟ほかは、書き写しの一致度を93%と報告）。
  2. 前衛の足元を、切り抜きを拡大した姿勢推定で精度よく取る。手前と奥で別のしきい値を使うことも検討する。
  3. それまでは、モーションの割合を論文の値と比べた結果を結論に使わない。
