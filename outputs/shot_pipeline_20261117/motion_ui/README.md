# 前衛モーションの判定確認（本人打球版 v3）

本人が `labels_human/human_labels_20261118.csv` に付け直した **without_candidates の32打球すべて**を対象に、W=0.4秒・D=0.3m の自動判定を確認する画面です。表示する判定は `v_human/net_motion/` の「箱の下端」「足首」の2つです。旧打球ラベル、Claude目視判定、廃止されたラリー別クリップには依存しません。

生成・テストは既存のPython環境、NumPy、Node.js、ffprobeを使用します。パッケージの追加は不要です。生成スクリプトの書込み先はこのフォルダの `data.json` のみ。ブラウザでの実画面確認はClaudeが担当します。

`--self-test` はPythonの5テストに加え、`node test_motion_ui.js --csv` によりJSの操作テストとダミーCSV書出しも実行します。JSだけを実行する場合は `node .\outputs\shot_pipeline_20261117\motion_ui\test_motion_ui.js`。

`file://` では開かずHTTPで使用します。動画は従来どおり `fetch → Blob → URL.createObjectURL` で読み込み、Range非対応のPythonサーバーでもシークできます。サーバー終了は `Ctrl+C`。

## 対象とデータの対応

| 自動判定 | なし | 単 | 複 | 判定できない | 合計 |
|---|---:|---:|---:|---:|---:|
| 箱の下端 | 7 | 18 | 3 | 4 | 32 |
| 足首 | 5 | 16 | 7 | 4 | 32 |

各方法とも判定可能28件、判定不能4件です。第8点手前を除く集計では判定可能25件ですが、画面では除外せず全件を出します。5点・6ラリー区間を対象とし、抽出はしません。IDを昇順に整列して `Random(20261118).shuffle()` で固定順にします。先頭は `p11_1_02` です。

- 判定：`v_human/net_motion/motions_main.csv`。存在しない場合は `motions.csv` から主条件だけを読みます。各方法32件、本人のpoint・frame・side・is_serve・rally_noと一致することをassertします。
- 打球と前後の印：本人CSVだけから取得します。「前」は同じ点・rally_no内で前衛側が最後に打った打球、「次」は同じ区間内の直後の打球です。区間をまたいで補完しません。相手の印は「本人ラベル」と表示します。
- 動画：`label_ui/clips/point_XX.mp4`。`label_ui/data.json` の `source_first_frame`、`frame_count`、fpsを使用します。生成時にffprobeで5本の実フレーム数・fps・1920×1080を照合します。
- 前衛の根拠：`v_human/net_motion/role_selection.csv` を短い日本語で表示。通常は相手の打球時に守備側でネットに近い方。サーブは次の打球時にネットから遠い方をレシーバーとみなしてもう一方を選びます。レシーバー本人の確認済みラベルではありません。`p09_1_01` は次の相手側の打球がなく前衛未選択のため、その理由を表示し、枠・軌跡なしでも確認できます。

## 操作と表示

1. 名前を入力し、手前N／奥F、前衛の枠、選択根拠を確認して「前衛の選択」を回答します。
2. 本人ラベルの相手の打球の瞬間が「正しい／ずれている／分からない」か確認します。「ずれている」はコマ送りで合わせ、ボタンか **T** キーで修正フレームを保存します。元の打球時刻は保持します。
3. 箱の下端・足首それぞれの **動きの有無・向き（3方向）・単／複** を「正しい／違う／分からない」で確認します。自動判定不能も「判定できない」と理由を表示します。向きや単複が「—」なら、その項目がないことを含めて確認します。
4. 「違う」があるか、正しいとした内容が食い違う場合は「正しい答え」を入力します。「正しい答えを自分で補う」でも入力可能です。判定できないときはその回答を記録できます。
5. 自信と必要ならメモを入力し「次へ」。最後は「完了する」、続いてCSVを書き出します。途中の書出しも可能です。

キー：`Space` 再生／停止、`←/→` 1コマ、`Shift+←/→` 6コマ、`T` 打球フレーム記録（ずれている選択時）、`Enter` 次へ。文字入力中は無効。動画クリックでも再生／停止します。

表示開始は `min(前の打球−0.2秒, 相手の打球−1秒)`、表示終了は `max(相手の打球＋1秒, 次の打球＋0.2秒, 自動区間の終点)`。前後がない場合は相手の打球±1秒を使い、クリップの中に切り詰めます。全32件で `first ≤ start ≤ contact ≤ end ≤ stop < first+count` と、シークするフレーム中心の時刻が動画長未満であることをassertします。

タイムラインには前・相手・次の打球、分類始点と＋0.4秒、必要なら修正打球を表示します。修正後も元の自動分類・軌跡は再計算しません。固定0.4秒はネット通過の実測ではありません。

軌跡は **`v_human/net_motion/trajectories_main.csv` の `raw_x_m/raw_y_m`** を、既存のコート変換の逆行列で1920×1080の動画座標に戻したものです。正規化は幅10.97m・長さ23.77m、canonical座標から動画座標への縮尺は1/2。既存 `outputs/ball_quality_20261110/match2_camera_transfer_pilot/protocol.json` を読み、箱由来の各座標は追跡CSVの独立した画面座標と誤差1e-5px以内で一致することをassertします。

描画は各方法の `contact_frame..end_frame` のみ。箱の下端は橙、足首は水色です。足首系の入力には箱への代替が含まれるため、件ごとに両足中点・片足・箱代替・欠測のコマ数を表示します。欠測をまたぐ線はつなぎません。実線矢印は取得できた最初・最後の点の変位、破線は自動判定の最終方向です。表示する生座標は、分類に用いた平滑化後の座標そのものではありません。古いpose cacheを直接読み直す処理はありません。

拡大表示は表示区間内の最初の追跡箱を中心とする、高さ3倍の正方形を640×640へ描画します。中心・倍率は再生・コマ送り・シークでも固定。元動画と拡大画面の軌跡・枠の表示切替は連動し、フレーム更新APIとその非対応時の処理を維持します。箱欠測は補間しません。方向ボタンとコートの小図は前衛の側に応じて切り替わり、手前Nは↑前、奥Fは↓前です。

単は一度まっすぐ移動、複は予備の後に決定の動き、複の向きは最終方向です。本人入力の斜め前／後ろは3方向の前／後ろに縮約します。自動の3方向は連続変位の45度境界なので、8方向からの縮約と境界付近で異なる場合があります。

## 保存とCSV

保存鍵は **`softtennis-motion-human-20261118-v3`** に変更し、旧保存は読みません。同じブラウザ・ホスト・ポートで再開してください。保存形式はversion=3。入力ファイルのSHA-256に基づくdataset_idが違う保存は上書きせず停止します。別タブで更新された場合も上書きを停止します。終了前にCSVを保存してください。

出力名は **`motion_review.csv`**。BOM付きUTF-8、データ32行。引用符・カンマ・改行はCSV規則でエスケープします。

| 列 | 内容 |
|---|---|
| id, point, contact_frame | ID、点、本人の元打球フレーム |
| corrected_contact_frame, contact_judgment | 修正フレーム、正しい／違う／分からない（画面の「ずれている」は「違う」） |
| player_judgment | 前衛の選択：正しい／違う |
| bbox_motion_judgment, bbox_direction3_judgment, bbox_complexity_judgment | 箱の下端の項目別の確認 |
| ankle_motion_judgment, ankle_direction3_judgment, ankle_complexity_judgment | 足首の項目別の確認 |
| motion, single_compound | 本人回答 none／motion／unknown、single／compound |
| screen_direction, player_direction8, player_direction3 | 画面方向、前衛から見た8方向・3方向 |
| feint, answer_origin | yes／no／unknown、accepted（確認内容から採用）／corrected（本人入力） |
| confidence, note, seconds, annotator, saved_at | 自信、メモ、作業秒数、名前、保存時刻 |

Claudeの判定列はありません。未確定項目は空欄／unknownとし、別の予測で勝手に埋めません。

計時は各件の**最初の操作から**開始します。開いただけ・再訪しただけでは増えません。累積秒数は保持し、自動の動画フレーム更新や定期保存は操作扱いにしません。60秒以上の無操作区間は区間全体を除外し、タブ非表示・項目移動時には停止します。長い無操作中の観察も除かれるため、厳密な観察時間ではありません。

`data.json` は区切り文字を `separators=(",", ":")` で詰め、**225,800バイト（256,000バイト未満）**。枠の表示座標だけ整数ピクセル、軌跡は0.1pxに丸めます。自動分類の数値は変更しません。

## 集計とテスト

```powershell
& .\study\.venv\Scripts\python.exe -X utf8 -B .\outputs\shot_pipeline_20261117\motion_ui\compare_motion_labels.py "C:\path\motion_review.csv"
```

集計は次を出します。

- 箱・足首の項目別正解率：`正しい / (正しい＋違う)`。分からない・未入力は分母外として件数を併記。
- 本人回答との一致：本人が枠を正しいと確認し、対象slotが同じで本人回答が確定した件。方向・単複は本人が動きありで該当回答がある件。自動判定不能は不一致。対象違い、未確認、本人不能、打球修正などは監査欄に表示。
- 本人回答の構成比と井箟ほかの値の表：有無、単複、単の3方向・8方向、最終3方向。本人の全件と第8点手前除外を並記し、各セルにn/Nを表示。枠の確認・対象slot・項目の確定が必要で、不能や欠損は分母外です。単複は動きあり、単方向は単、最終方向は動きありを対象にします。採用回答数と本人不能・未入力なども表示。
- 打球の修正件数、未入力件数、修正−元のフレーム差、絶対差の平均・中央値・最大。修正行も元分類との比較に含むため、その件数を表示します。

井箟ほかの値は `v_human/net_motion/paper_comparison.csv` の継承値です。原論文は今回再照合しておらず、単8方向の合計101.9%という不整合も保持し、再正規化しません。

テストは本人CSVとの全32件の対応、前後の打球、前衛の根拠、2方法の分類・方向、入力ハッシュ、固定順、全表示範囲、容量を確認します。JSでは方向変換、採用／矛盾／不能、必須回答、Tキー、両フレームAPI、拡大の固定座標・表示連動、最初の操作からの計時、60秒境界、**全32件の移動と完了**を検証します。JS exporterのダミー32行をPython loaderから集計CLIまで通し、引用符・カンマ・改行、重複ID検出、構成比の分母を確認します。ダミーCSVの一時フォルダはmotion_ui内に作成して終了時に削除します。

予測を提示する確認作業なので、本人の確認による正解率は独立した盲検評価ではありません。accepted回答と元予測の一致には循環性があります。本人が付け直した正しい打球時刻が、前衛選択・追跡・モーション分類の正しさまで保証するわけではありません。同一試合の32件の構成比を論文と並べることは参考比較であり、汎化精度や再現性の証明にはなりません。
