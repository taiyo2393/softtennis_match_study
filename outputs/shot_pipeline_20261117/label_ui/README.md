# match2 打球ラベル・作業時間記録

研究者本人が第7〜11点の映像を確認して打球を付ける、オフラインの予備実験用画面です。HTML / CSS / 素のJavaScriptのみを使います。外部ライブラリ、CDN、外部通信、動画のアップロードはありません。ローカルサーバーは読み取り専用で、記録はブラウザ内に保存します。

## 明朝の開き方

リポジトリ直下 `C:\Users\ta239\Research\softtennis_match_study` の PowerShell で実行します。

```powershell
# 生成済みなので、通常はこのサーバー起動だけで使えます。
& study\.venv\Scripts\python.exe -m http.server 8765 --bind 127.0.0.1
```

サーバーを動かしたまま、次のURLをブラウザで開きます。

<http://127.0.0.1:8765/outputs/shot_pipeline_20261117/label_ui/index.html>

`index.html` の直接ダブルクリックでは `fetch` が失敗する場合があります。URLは毎回同じものを使ってください。`localhost` と `127.0.0.1`、ポート、ブラウザ・プロファイルが変わると保存先が分かれます。作業タブは1つにします。

1. 作業者名（既定は空）、点・ラリー、条件を選択します。「候補あり」は既定v1。必要なら開始前に「v2 kept」に変更します。
2. 最初の再生・移動・ラベル操作で計時が始まります。選択しただけでは始まりません。映像をクリックすると再生・停止し、その後キーを使えます。
3. 打球位置で N / F、サーブなら S、最後の打球の結果を E で設定します。
4. Enter または「このラリーを完了」で記録を固定します。空ラベルでの完了は防ぎますが、打球の網羅性は本人が確認してください。
5. 「CSV を書き出す」で **ラベル・作業記録の2ファイル**を保存します。ブラウザから複数ダウンロードの許可を求められたら、このローカルページを許可してください。2つともダウンロードされたことを確認します。
6. 必要なら「全記録の JSON を保存」で操作イベント・離席区間を含むバックアップも保存します。完了後に比較ボタンを押すと、Claude のラベルを薄く重ねます。

CSV / JSON はブラウザのダウンロード先に保存され、リポジトリに自動では書き込まれません。読み込み済みJSONを画面に取り込む機能はありません。別PCへの移行はバックアップ原本を保管してください。

## 操作

| キー | 操作 |
|---|---|
| Space | 再生・一時停止（音声あり） |
| ← / → | 1フレーム移動して停止。Shift併用で6フレーム |
| J / K | 前 / 次の音の候補へ移動して停止。「候補なし」では無効 |
| N / F | 現在フレームに手前 N / 奥 F の打球。±10F以内の最も近いラベルがあれば、その位置と側を更新 |
| S | 現在位置±10Fの最も近いラベルのサーブを切替。先に N / F を押す |
| Backspace / Delete | 現在位置±10Fの最も近いラベルを削除 |
| E | 最後の打球の結果を unknown → winner → out → net → unknown と循環 |
| Enter | ラリーを完了。以後その試行のラベル・作業時間・再生時間・操作数を固定 |

ラベルまでの距離が同じなら早いフレームを優先します。±10F以内に別々の打球を作ることはできません。これは今回指定された操作仕様の制約です。手前は青い●、奥は橙の◆、サーブは★です。結果は最後のラベルのみ4択とし、途中の打球は `continue` です。ラベルの追加・削除で最後が変わった場合は結果を再確認してください。

タイムライン全体は前後の余白を含むクリップ、背景の帯が `intervals.csv` のラリー区間です。クリックで任意位置へ移動します。下のラベル一覧からも移動できます。「候補なし」でも**映像の音は残り**、候補の線と J / K の支援だけがなくなります。

入力欄・選択欄・ボタンにフォーカスがある間は、ラベル用キーを無効にします。キーが効かない場合は映像かタイムラインをクリックしてください。シーク中はラベルを付けず、表示フレームの確定を待ちます。

`requestVideoFrameCallback` があれば `mediaTime` から実際に提示されたフレーム番号を計算します。未対応時は `currentTime` を使用します。1フレームは `1001/60000` 秒。移動先は整数フレームの時刻に丸め誤差対策の1マイクロ秒を加えます。元動画のフレーム番号は0始まりです。表示時刻も同じフレームから求めます。

## 計時と保存の定義

- **経過時間**：最初の記録対象操作から完了までの実時間。未完了なら現在時刻まで。
- **無操作時間**：操作間隔が **60秒以上** のとき、その間隔全体（最初の60秒を含む）。ラリー・条件・試行切替、非表示タブ、ページを閉じていた時間も、60秒未満を含めて除外します。重複する区間は和集合にして二重計上しません。
- **作業時間 `active_seconds`**：経過時間 − 無操作時間。60秒に達すると、それまで暫定的に作業時間だった60秒も無操作へ移るため、画面の作業時間が減ることがあります。
- **再生時間 `playback_seconds`**：`playing` 中の実時間の累積。繰り返し再生は加算し、シーク距離、一時停止、バッファ待ち、完了後の再生は含めません。速度は1倍固定です。
- **操作数**：再生・停止、1F/6F移動、候補移動、タイムライン・ラベル一覧からの移動、N/F/S/削除/E、音量、完了を種類別に記録。N/F/S等の空振りも `changed:false` のイベントとして数えます。自動更新・設定選択・CSV保存・完了後の閲覧は数えません。
- **作業者・条件の固定**：名前は計時開始後、候補版は計時開始後に固定します。条件を切り替えると別試行へ移ります。候補なしは `candidate_version=none`。ラベルは引き継ぎません。
- **再開**：同じ名前・点/rally・条件・候補版の最新試行を開きます。「保存済みの試行」から過去の記録も開けます。完了済みは編集できず、「同条件で新しい試行」で別IDの空の記録を作成できます。
- **比較**：完了後のみ表示可能。比較の時刻を保存し、同じラリーで比較後に始めた試行には `reference_exposed_before_start=true` を付けます。比較を隠しても閲覧履歴は消しません。
- **自動保存**：各操作・切替・完了時と、作業中は約1秒ごとに `localStorage` に保存します。すべての読み書きに try/catch があります。保存領域が使えないときは画面に通知し、メモリ内で作業を継続します。閉じる前にCSVとJSONを保存してください。壊れた保存データを検出した場合は自動上書きを止めます。
- **中断**：正常なタブ非表示・終了はその時刻から除外。ブラウザの強制終了は最後の保存チェックポイントから中断として扱うため、最後の約1秒の情報が失われる可能性があります。PCをスリープするときも、一度別タブへ切り替えてください。PCの時刻を作業中に変更しないでください。

操作がなくても映像を見て判断している場合があります。そのため無操作補正値は「人の認知的作業時間」の直接測定ではありません。`elapsed_seconds` と `active_seconds` を併記し、60秒閾値による除外の影響を点検してください。

Web Locks 対応ブラウザでは同時作業タブを1つに制限します。未対応時はタブ間通知と保存変更通知で競合を検出します。保存記録はブラウザデータ削除で失われるので、CSV/JSONも保管してください。

## 書き出すデータ

ラベルCSVの基本列：

`point, rally, frame, side, is_serve, outcome`

混同を防ぐため `trial_id, participant, condition, candidate_version, status` も付けます。`side` は N/F、`is_serve` は true/false。

作業記録CSVの基本列：

`point, rally, condition, start, end, active_seconds, idle_seconds, n_actions_by_type`

追加列：`participant, trial_id, candidate_version, status, elapsed_seconds, away_seconds, playback_seconds, compared_at, reference_exposed_before_start`。

`start/end/compared_at` はUTCのISO 8601（末尾Z、日本時間は+9時間）。`condition` は `with_candidates` / `without_candidates`。`n_actions_by_type` はJSON文字列で、CSVとして引用符をエスケープします。CSVはUTF-8 BOM付きです。`away_seconds` は無操作時間に含まれる離席時間の内数で、加算し直してはいけません。

両CSVには**全試行**を含め、未完了は `status=in_progress`、`end` 空欄にします。計時前の空の試行は出力しません。本集計では `completed` のみを使い、重複試行を `trial_id` で識別してください。JSONには全操作の時刻・種類・対象フレーム、離席区間も残ります。

## 生成し直す

```powershell

# 既存クリップも再エンコードする場合は --force
```

`audio/intervals.csv` は `[start_frame, end_frame)`。前後60Fを加えた範囲を、`tracking/point_07/protocol.json` の `source_video` から切り出します。H.264 / yuv420p / veryfast / CRF23、AAC 160kbps、60000/1001 fpsを維持し、faststartを付けます。元動画・既存データは変更しません。

`data.json` には6クリップのファイル名、元動画の先頭フレーム、フレーム数、fpsの分子分母、元ラリー区間、v1候補・v2 kept候補、Claudeの比較用ラベルを格納します。候補なしでもデータファイルには候補と参照ラベルがありますが、作業画面では隠します。作業前に元CSVやdata.jsonを見ないでください。v2ファイルがない場合は空配列となり、画面でv2を選べません。

生成時はOpenCVで、クリップ先頭・末尾を元動画の指定位置と前後±3Fに照合します。480×270のグレースケール画像の平均絶対差（MAE、0〜255）が、ずれ0で最小かつ8未満であることをassertします。入力側 `-ss` を使い、照合失敗時は出力側 `-ss` で再生成して再検証します。フレーム数・H.264・yuv420p・AAC・fps・動画開始時刻0もassertします。詳細は `verification.json`。

## 明朝の予備実験と評価案

まず1ラリーで、名前→条件選択→再生→1F移動→N/F→S→E→Enter→2CSV保存まで試します。画面を別タブに10秒ほど切り替え、戻った後に離席分が除外されることも確認できます。この動作練習を本評価に含めないでください。長い無操作除外は別の練習試行で確認します。

**本人1名・1ラリーの試行で確認できるのは、操作性・記録可能性・所要時間の事例です。候補による一般的な短縮効果や精度改善はまだ主張できません。**

比較を進めるときは次を先に固定します。

1. 問いは「候補線と候補ジャンプが、同等の打球検出精度を保って、固定ラリー区間のラベル付け時間を減らすか」。音声・映像・通常キー操作は両条件で同じ。v1/v2は途中で混ぜません。
2. 練習用と評価用を分けます。同じラリーを続けて両条件で付けると記憶と習熟が交絡します。複数人へ拡張するときは条件順序を釣り合わせ、長さ・打球数等が近い未見ラリーを条件間で割り当てます。本人だけの繰返しは探索的な結果と明記します。
3. 音候補の設定選択には第7・8点が使われています（既存audio/README参照）。候補の汎化を論じるなら第9〜11点を優先します。ただし、この3点も今回の小規模予備実験であり、独立参加者・新しい試合の検証は別に必要です。
4. 精度の正解は、候補と今回の回答を見ずに元映像から別途確定します。可能なら別の評定者によるラベルと不一致の協議を行います。Claudeとの比較は「一致」であり「精度」ではありません。判別不能はフレーム許容幅を広げて正解にせず、件数と扱いを明示します。
5. 主指標は完了試行の `active_seconds` / ラリーと、打球の適合率・再現率・F1。対応は同じ点/rally内で1対1、最大対応数を優先し、次にフレーム誤差を最小化します。許容幅を事前に固定（例：主解析±6F、感度分析±10F）。対応打球の絶対フレーム誤差、側・サーブ・最後の結果の一致も別々に評価します。ラベル未対応・参照未対応を除外せず、誤検出・見逃しとして数えます。
6. `elapsed_seconds`、`idle_seconds`、再生時間・操作数も併記します。速くなっても見逃しが増えた場合は改善と結論しません。少数試行では個々の値と分布を示し、打球を独立した被験者として扱う検定をしません。
7. **1点あたり**を報告するとき、第7点はA/Bを別試行として記録してから、同じ作業者・条件・候補版のA+Bの時間を合算します。Aだけ・Bだけなら「1ラリーあたり」と報告してください。Aは得点に結び付かない再サーブ前の流れを含む可能性があり、独立した得点1件と数えません。切替中の時間は合算値に入りません。

区間は既存ラベルに基づいて与えられているため、この予備実験は「ラリー区間が既知のときの打球付与」を測ります。試合全体から区間を探す時間を含む「全工程の1点あたり作業時間」とは区別してください。

[EventAnchor（Deng et al., CHI 2021）](https://ssxiexiao.github.io/papers/eventanchor.pdf) は支援機能のある画面と比較用画面を用い、練習・条件順序への配慮の下で時間と誤りを比較しています（§6）。本画面はその比較の考え方を参考にしていますが、論文の実験の再現ではありません。今回のラリー完了時間と無操作補正は本予備実験独自の定義です。候補提示そのものを新規性として主張せず、対象条件での効果と限界を測ってください。

- 1フレーム送り（F22716 → 22719）
- 候補への移動（K で F22799、F22812。`audio/candidates.csv` と一致）
- 手前・奥のラベル付け
- 計時と操作回数の表示

CSV の書き出しと「完了」は、まだ試していない。
