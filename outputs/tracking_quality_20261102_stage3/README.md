# 設定固定での追加ラリー確認（2026-11-02）

第2段階で開発に使った044/056以外へ、同じ検出器・閾値・割り当て規則を適用した。
設定と対象区間は推論前に `predeclared_protocol.json` へ保存し、コード・重み・
ByteTrack設定のSHA256を処理後も確認した。元の研究データや人手ラベルは変更していない。

## 対象

同じmatch1内の002・005・048。以前のサービス接触候補を起点に、既存の主カメラ候補区間内、
最大900ソースフレーム（約15秒）。厳密に人手確定したラリー全長とは呼ばない。
これらには過去の単一画像等の確認があるため、完全未使用の外部評価でも別試合評価でもない。
第2段階の連続追跡を適用する新しい区間である。

## 結果

| 区間 | 自動初期化 | 処理対象 | 同時4枠の出現 |
|---|---|---:|---:|
| 002 | 4人の候補を選択 | F2223〜2577、355フレーム | 140 / 355（39.4%） |
| 005 | 保留：手前2人・奥1人しか初期選択できない | F8607〜9051、445フレームの検出を実行 | 4人追跡は開始せず |
| 048 | 4人の候補を選択 | F125859〜126758、900フレーム | 330 / 900（36.7%） |

同時4枠の出現は本人同定精度ではない。遮蔽や画面外の区間を全て誤りと数えていない。
005を集計対象から黙って除外せず、自動初期化の保留として残した。
結果を見て対象開始時点や閾値を変更することは行っていない。

002では手前後衛の82フレーム（約1.37秒）と奥側の184フレーム（約3.07秒）の
連続した割り当て欠落がある。048では奥側に546フレーム（約9.11秒）の欠落がある。
この長さは「選手が見えているのに誤った時間」の測定ではなく、枠を割り当てなかった長さ。
005開始時の画像では奥側の対象選手が手前選手と重なっている。
002/048の開始画像の4候補はAIで視認したが、全軌跡の独立した本人ID正解は未整備。

## 制約が明確になった点

- 開始時点に4人が見えないと、後から見える場面があっても現在の実装は初期化しない。
- 現在の割り当ては、最後の観測から90フレームを超えるとその人物を候補へ戻さない。
  そのため長い遮蔽・画面外移動の後の自動再取得に構造的な制限がある。
- 初期1枚の服特徴を固定する方式と同一ユニフォームの2人の識別には限界がある。
  ただし各欠落の発生原因がすべて服特徴であると実証したわけではない。

044/056の見た目が改善したことだけで、他のラリーでも安定しているとは結論できない。
今回の区間の可視性や展開も違うので、出現割合の差をそのまま精度低下とは解釈しない。

元の人物検出行の維持、割り当ての一対一性、非補間、コード・重みのハッシュ一致を検査した。
ファイルのデコードやプログラム検査は、全フレームのID精度確認を意味しない。

次の改善対象は「4人が確認できる時点からの自動初期化」と「長い欠落後の再取得」。
今回の固定設定の結果は残し、新しい方式は別バージョンで比較する。
長い欠落の上限だけを緩める方法は線審や相方への誤対応を増やす可能性があるため、
復帰候補の複数フレーム確認と競合判定を合わせて検討する。
