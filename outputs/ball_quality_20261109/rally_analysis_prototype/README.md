# ラリー配置と得点側：分析データの構築試作

**044・056の選手位置、整備済み球位置、既存の人手得点側を、記録上の整数source frameで結合した。** 計577注釈時点を保存し、各ラリーの序盤約1秒・31時点から比較用の特徴を作成した。追加の人手入力、モデル学習、得点との統計的関連の推定はしていない。

## 今回の具体的な研究案

問いは「ラリー序盤のペア配置が得点側の識別に寄与するか。球情報を追加する便益はあるか」。まず選手配置を主入力にし、時間をかけて整備する球情報の価値を比較で判断する。

|比較|使う入力|確かめること|
|---|---|---|
|基準|学習側の多数派得点側|配置を使わない基準を上回るか|
|A|固定した最後の1時点の選手配置|1時点の情報で足りるか|
|B|固定した約1秒の配置の要約|欠測に配慮した短区間の要約に価値があるか|
|C|B＋球の画像座標と観測マスク|球の整備コストに見合う追加情報があるか|

これは比較の設計であって、効果が確認できた結果ではない。配置から得点側を識別できても、戦術の因果効果や失点した理由を証明したことにはならない。

## F1/F2の順序に依存しない配置

各ペアの2人から、画像上の中心x/yと、2人のx方向・y方向の隔たりの絶対値を計算する。ペア内で選手ラベルを交換しても同じ値になる。

- 手前ペア・奥ペアのそれぞれ4値、計8値。
- 1人でも未観測ならそのペアの値を空欄とし、観測マスクを残す。
- 別人・審判・相手側への誤対応や座標誤差は、この表現では解決しない。
- 「前衛」「後衛」の役割分類や個人別の戦術を、順序不変な特徴から復元したとはしない。

人物は箱の下端中央という代理点。元3840×2160を1920×1080へ合わせ、特徴は画像の幅・高さで正規化する。接地した足元の正解やコート上のメートル座標、ボールの三次元位置・物理的球速へ変換しない。

## 時間範囲と観測数

既存の有効サービス接触候補区間の後にある、最初の整備済み注釈時点をt0とし、t0〜t0＋60元フレームを2フレーム間隔で使う。約1.001秒・31時点に固定する。都合のよい時点や「最後に見えた時点」へ選び直さない。

|ラリー|入力source frame|4人の観測が揃う時点|球位置あり|得点側の人手確認|
|---|---|---:|---:|---|
|044|115375〜115435|29 / 31|27 / 31|手前|
|056|154088〜154148|27 / 31|27 / 31|手前|

044の最後の要求時点は選手が3人で、奥ペアの1時点特徴は欠測になる。約1秒の窓全体では29時点に4人の観測がある。この違いは、1時点と短区間の要約を比較する動機になる。ただし、観測数は本人同定精度ではなく、要約で予測が改善した結果でもない。

入力末尾は、既存の最初の終端候補より044で341、056で692元フレーム前にある。終端区間そのものは独立に正確なフレームへ確定した値ではない。

`prefix_diagnostic.jpg` はt0・約0.5秒・約1秒の診断図。橙は手前ペアの位置候補、水色は奥ペア、緑は整備済み球位置。得点側やスコア画像をモデル入力に使う図ではない。母画像・座標は既存のものをそのまま使い、欠測を埋めない。

## 得点側と既存データの再利用

人手で得点側が確認済みのラリー候補は**11件（手前7・奥4）**。最新の `human_review_log.csv` とラリー表を照合し、025の手前への訂正も保持して抽出した。チーム名は人の側回答とスコア等から導出した値なので、別の独立したチーム正解として扱わない。

この11件のうち8件に連続選手位置の出力素材が見つかった。002・003・005・007・025・044・048・056である。出力ファイルの存在を「全員を正しく追えた」「開始・終端が確定した」「全て分析適格」とは呼ばない。

今回、球まで結合した2件は**どちらも手前得点**なので、得点側の識別性能を検証できない。モデルを当てはめて見かけの正解率を出さず、データ構築の試作に留める。残る既存素材については、開始根拠と位置品質を引き継いで入力範囲を整えることが次の作業になる。

既存63候補の確認状況は `existing_rally_inventory.csv` に記録した。未準備の欄を、選手が見えない・ラリーが無効である証拠にせず、元の `analysis_eligible` を書き換えていない。050・051は同じポイントという人手確認を同じgroup IDで保持し、将来の分割で別の独立ラリーへ分けない。他のsingleton groupもポイントの独立性が完全に監査済みという意味ではない。

## 情報漏れと評価範囲

モデル入力の許可列は `feature_schema.json` に明記した。得点側・チーム名・終端候補・全ラリー長・全体の出力率・修正時間や修正の種類・ファイル名・source frame番号を特徴に入れない。ラリーIDは結合キーで、学習入力から除く。

1時点特徴は最後の要求時点の値。短区間の要約は同じ31時点内の平均と、両端が観測された場合の末尾−先頭差、およびペア観測率を使う。差は画像上の2端点の変化で、途中の軌跡補間や物理的な速度を意味しない。球は同じ窓内の画像座標と観測率を追加し、要求時点に球がなければ末尾座標は空欄のままにする。

座標の生成元には、双方向の人物追跡、クリップ全体の背景median、動画全体を見た人の修正がある。入力座標を得点前の時点に制限したが、処理全体が未来情報を使わないオンライン予測だと主張しない。予測採用・修正のある球座標を、独立した位置精度評価の正解へ転用もしない。

本比較を行う際は、同じポイント・ラリーを学習と評価へ分けず、複数試合が揃えば試合単位で分割する。単一試合のブロック別・ラリー群別確認は同一試合内の探索と明記する。正規化、欠測値の処理、設定選択は学習側だけで決める。フレームを無作為分割した見かけの大量標本にしない。30〜50ラリーもデータ成立性の予備規模であり、それだけで本評価の十分な標本数とは決めない。
