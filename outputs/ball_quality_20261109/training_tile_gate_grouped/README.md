# 追加タイル候補の採用判定：クリップ別の内部検証

2026-11-09。前段の拡大補完は、現行66正解・4誤出力から77正解・14誤出力へ変わった。追加の11正解を保ちながら、追加誤出力10件を抑えられるか調べた。

## 結果

| 方式 | 16px以内の正解 | 誤出力 | 現行の正解の喪失 |
|---|---:|---:|---:|
| 現行の固定時系列方式 | 66 | 4 | — |
| 拡大候補をそのまま補完 | 77 | 14 | 0 |
| 拡大・細部対照の位置一致で採用 | 72 | 5 | 0 |
| 10特徴の学習判定・クリップを外した予測 | 77 | 7 | 0 |

学習判定は、追加正解11件をすべて保持し、追加誤出力10件のうち7件を抑えた。残った追加誤出力は位置違い1件と、人が球を観測できないという回答の2時点への出力である。これは現行方式の4誤出力へさらに3件を加えた結果なので、事前条件の「誤りを増やさない」を満たしていない。

固定の位置一致条件は追加正解6件を保持した一方、5件を落とし、追加の位置違い1件を残した。どちらも採用候補に選ばず、全データでの最終判定器の学習、validation・audit・新52時点への追加推論には進んでいない。既存の正規追跡も更新していない。

## 学習対象と分離

固定済みnative最大ピーク候補は88時点に存在した。このうち手動中心を持つ81候補を学習用に使用した。中心から16px以内76候補を正例、16pxより離れた5候補を位置違いの負例とした。

この負例は「対象の手動中心と一致しない」という意味であり、物体が一般的な非ボールであるという注釈ではない。別の球や準備中の球の可能性を自動で否定していない。球が観測できないという回答の7候補は中心位置がないため学習から除外し、球の物理的な不在を教える負例にもしていない。これらはクリップを外した予測でのみ出力の有無を検査した。

8クリップを一つずつ外し、残り7クリップの位置注釈だけで標準化と分類器の学習を行った。各クリップの候補は、そのクリップのラベルを使用しないモデルで判定した。ランダムなフレーム分割は使わない。入力4画像のハッシュも学習・確認クリップで重ならないことを確認した。

## 固定した判定条件

学習判定の入力は、nativeのpeak・bbox平均、成分画素数のlog、矩形の充填率、縦横比のlog、重複領域での16px以内の一致率、degradedの16px近傍peak・最近候補までの距離、タイル端からの距離、32pxより離れた競合候補とのpeak差の10特徴。絶対座標・時刻・クリップID・手動中心は特徴に含めていない。

分類器は従来と同じクラス均衡付きlogistic損失とL2係数1、CPU float64、LBFGS300、ゼロ初期値、固定採用閾値0.5とした。閾値や特徴数・正則化の追加探索はない。値は校正された正解確率ではない。

固定の位置一致対照は、選択済みnative中心から16px以内にdegradedの候補が一つでもある場合に採用する。特徴と基準は推論・学習前の `protocol.json` に保存した。

適用範囲は現行の出力がない時点だけ。現行70出力の座標・有無・confidenceをそのまま保持し、採用する座標は固定済みタイルの実成分中心だけである。元の正解66点を保持できることは処理上の保証であり、分類器が全既存正例を正しく認識したという意味ではない。実際、候補単体では学習判定が76正例の74件を保持し、位置違い5件のうち1件を残した。

## 検証と制約

別スクリプトで88特徴行、8モデルの学習対象・平均・標準偏差・ハッシュ、保持クリップの88スコア、123時点の出力と成否を再現した。手動中心を持たない7候補が学習へ入っていないこと、各方式で元70出力を完全保持すること、モデル・注釈・確認済み追跡の不変も確認した。

今回の内部分離はクリップ単位で、試合単位ではない。位置違い負例は5点・3クリップに限られ、十分な負例の多様性を検証できていない。内部予測で2方式を比べることも方式選択であり、独立した外部性能とは扱わない。元の学習用123時点には準備中・移行も含まれるため、プレー中だけの精度や試合全体への効果にも読み替えない。

正解77点を保って誤出力を14→7へ減らす内部結果は得られたが、自動採用の条件には未到達である。次に必要な検討は、残った誤位置・観測不能時点への追加出力を抑えられる材料があるかであり、この3件だけに合わせた例外ではない。

条件は `protocol.json`、結果は `grouped_comparison.csv`, `result.json`、分離は `folds.json`、検証は `verification.json`。`remaining_added_errors.csv`, `rejected_additions.csv`, `addition_effects.json` に追加出力の内訳を保持した。8モデルは内部検証用であり、現行への参照や最終モデルにはしていない。
