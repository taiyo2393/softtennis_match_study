# 044：時系列だけの候補選択を既存確認例で再検証

対象は確認済みの実球8候補・誤検出4候補（local1083–1093）。新しい目視確認は要求していない。
分割入力比較動画に表示した候補を入力とし、正誤ラベルは選択処理の後に読み込んだ。
ただし失敗例をすでに知った上での開発検証であり、独立・盲検の評価ではない。

| 選択方式 | 実球候補の保持 / 8 | 誤検出候補の選択 / 4 |
|---|---:|---:|
| 強度最大 | 8 | 3 |
| 前向きの最近傍 | 7 | 4 |
| 後ろ向きの最近傍 | 8 | 3 |
| 前後方向の一致 | 7 | 3 |
| 速度予測に基づく距離制約 | 8 | 2 |

前後方向一致の最近傍は既存`propose_044_ball_branches.py`の距離・曖昧性条件をそのまま再利用。
速度方式は16+4×経過フレームpxの予測残差制約、速度更新重み0.5、最長12フレーム、競合候補の距離差12pxを用いた新しい説明用試作。
失敗例を見た後の条件であり、最適化や妥当性検証を済ませた値ではない。条件の探索・反復調整はしていない。
始終点1080・1096は未修正モデルの出力から候補を初期化し、区間内の人手訂正座標を選択処理へ渡していない。
これらの始終点も独立した正解ではないため、成功結果が仮にあっても一般性能とは扱えない。

## 結論

5方式とも、実球8候補を保ちながら誤検出4候補をすべて避ける条件を満たさなかった。
とくに速度方式は1090・1091-Aを避けるが、1092・1093の誤検出を選ぶ。
1092は1091-Bの実球から約4.08px、速度予測位置から約3.91pxで、20pxの予測残差制約を通過する。
**近距離・高強度・前後の接続だけでは、その成分が実球であることを保証できない。**

この数は候補単位の既知の失敗確認で、物理的可視性・球中心精度・独立した追跡精度ではない。
CSV中の`qualifies_for_adoption`はこの最小反例チェックの通過フラグに過ぎず、仮に通過しても別ラリーでの評価を要する。
今回の5方式はすべて0。自動採用・補間・確認済み入力の更新は行わず、`../integrated_044_v4/`を維持した。

`protocol.json`に実行前の候補入力・条件・ハッシュ、`policy_selections.csv`にラベル照合前の選択結果、
`reviewed_candidate_outcomes.csv`に候補単位の正誤照合、`decision.json`に判断を保存した。
確認済み球・人物・統合レジストリ・元ラリー注釈のハッシュは実行前後で保持した。
