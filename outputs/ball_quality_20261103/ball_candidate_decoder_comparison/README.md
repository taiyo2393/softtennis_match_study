# 元モデルの候補選択だけを変える固定比較

## 結論

既定の3種類のスコア選択は、今回確認した学習難例A/C/DのうちC/Dを選び直せた。しかし、固定validation120件では出力座標が全て従来と完全一致し、正解80・誤出力3のままだった。学習難例での2件改善を評価成績へ足さず、事前の同点時ルールに従い正規の選択方式は元の最大外接矩形面積を維持した。auditの読み込み・推論・代替方式選択は行っていない。

既存validationの候補競合は4フレームしかなく、残りは候補なし37・候補1個79である。この評価だけで今回の候補競合問題に対する有効性を十分に判断できない。単純スコア方式が一般に無効、又は従来方式が十分正確という結論は出さない。

## 学習・閾値・候補座標を変えない比較

`compare_ball_candidate_decoders.py`でプロトコルを先に保存し、元BallTrack重み・閾値0.3・二値化・全外側輪郭・外接矩形中心を固定した。前段の追加学習済み重みは用いない。以下の4規則を同じヒートマップに適用した。

| 規則 | 選択基準 |
|---|---|
| bbox_area（従来） | 成分の外接矩形のw×hが最大 |
| component_peak | 成分内の閾値超過画素の最大値が最大 |
| bbox_mean | 外接矩形全体の平均値が最大（従来Confidenceと同じ計算） |
| component_mean | 成分内の閾値超過画素の平均値が最大 |

全規則で同点は面積、さらに元の輪郭順で解決する。候補の追加・削除、座標の再推定、スコア閾値の調整、時系列補間、分類器学習は行わない。存在/欠測の出力が規則間で変わらないことを検査した。スコアは未校正のヒートマップ値であり、実球の確率とは呼ばない。

固定validationだけで「従来の正解80件全保持・誤出力3以下」を満たす方式から、正解数、誤出力数、事前の方式順で選ぶ。元方式を同点時の先頭に置いた。厳密に改善した方式だけ次に固定audit60件で点検する計画だったが、今回は改善方式がなくauditを使っていない。

## 結果と評価範囲

| 規則 | 固定validationの正解位置 | 誤出力 | 従来の正解を失った件数 | 学習難例3件の正解位置 |
|---|---:|---:|---:|---:|
| bbox_area | 80 | 3 | 0 | 0 |
| component_peak | 80 | 3 | 0 | 2 |
| bbox_mean | 80 | 3 | 0 | 2 |
| component_mean | 80 | 3 | 0 | 2 |

正解位置は手動中心から元画像16px以内、誤出力は誤位置と非可視注釈への出力の合計。難例3件は追加学習側の注釈であり、方式選択にもvalidation/audit集計にも使っていない。Bはユーザーがプレー後と記載したため本比較の難例診断には含めない。

Aの実球候補の最大値は約0.309、別候補は約0.524であり、最大値だけではAを救えない。Cは約0.559対0.550、Dは約0.619対0.607でスコア選択が実球側を選んだ。差は小さく、対象1フレームの成功から前後の追跡安定性は主張しない。

validationには可視注釈105件があり、どれかの成分中心が16px以内にあるのは81件、実際に従来規則が選んだ正解は80件だった。この固定候補集合で選択だけを理想的に変えても正解数の上限は81件である。これは人手正解を参照した診断上の上限であって、実装可能な選択精度ではない。既存の欠測を候補選択だけで解消できるわけではない。

同一試合内で以前から見ている疎な評価標本で、準備中・切替等も含まれる。主プレー中や別試合の追跡精度は未評価。候補競合を含む主プレー区間の評価を整える必要があり、同じ120件で選択ルールの探索を増やすだけでは不十分である。
