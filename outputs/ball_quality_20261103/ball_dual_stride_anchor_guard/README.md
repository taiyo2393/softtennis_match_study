# 前後支持による欠測補完の追加確認：不採用

`../ball_dual_stride_path_comparison/`の固定4案が学習側で誤出力を増やしたため、学習結果だけを受けた1回の追加確認として実施した。新方式の評価側への適用前に、`training_protocol.json`へ候補・支持条件・採否を保存した。

実際の同時点候補だけを出すmissing_only_union_pathに、以前からある`evaluate_observed_ball_fallback.decide`を変更せず適用した。元の連続入力の全フレームraw出力を両側の支持とし、欠測8元フレーム以内、線形参照から16px以内、既存カメラ保留を要求する。線形参照は採否の条件であって、補間座標を出す処理ではない。

学習側123時点で、以前の時系列方式は正解66・誤出力4、無保留の併用補完は正解70・誤出力6、今回の保留付き補完は正解69・誤出力6。元の正解66件と元70出力は全て保持するが、2つの追加誤出力を残し、正しい補完007/608を1つだけ棄却した。線形参照との距離は約34.01px。この場面で実際にバウンドしたか、支持側の出力が誤っていたかは未確定。

既存名`add_observed_finetuned_candidate`がCSVに残るのは共通関数の状態名を再利用しているためで、この候補を追加学習したモデルから作ったという意味ではない。今回のモデル重みは元のままである。

誤出力を増やさないという条件を満たさず不採用。支持半径・長さ・画像条件の再調整、評価120件やauditへの新方式適用、新規注釈は行わない。006/341の非可視注釈を物理的な球不在の確定へ変換しない。旧注釈・人手訂正・正規参照・モデル重みは保持する。

`training_selection.json`、`training_gate_decisions.csv`、`discarded_candidate_diagnostics.csv`、`verification.json`に検証記録を保存した。これは既知の同一試合の学習側での開発結果であり、一般化性能を示さない。
