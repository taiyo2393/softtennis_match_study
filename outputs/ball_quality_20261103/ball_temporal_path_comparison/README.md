# 前後の検出候補をつなぐ局所経路による選択

## 結論

学習側だけで数値設定を選び、設定を固定してから既存validation・プレー確認済み4対象・追加auditを順に点検した。元の正解を失わず、候補の誤選択を減らす結果が得られた。元モデルの重みや検出閾値、正規の追跡レジストリ、既存の人手訂正は変更していない。

| 用途 | 対象フレーム数 | 正しい位置：元→時系列 | 誤位置/誤出力：元→時系列 | 元の正解を失った件数 |
|---|---:|---:|---:|---:|
| 設定選択用（学習側） | 123 | 63→66 | 7→4 | 0 |
| 既存validation | 120 | 80→81 | 3→2 | 0 |
| 人手でプレー中と確認した難例 | 4 | 2→4 | 2→0 | 0 |
| 追加audit | 60 | 34→35 | 5→4 | 0 |

正しい位置は元1920×1080画像の手動中心から16px以内。誤位置/誤出力は可視球への誤位置と、非可視注釈に対する出力の合計。各用途の成績は合算しない。欠測と球不在への誤出力は変わらず、今回の改善は既に出ている候補の選び直しによる。

これは同一試合内の疎な注釈での開発結果である。今回の4難例の失敗を知った上で時系列方式を設計している。数値設定の選択に4件の座標は使っていないが、4件は未使用の独立テストではなく再確認用である。旧validation/auditも過去の実験で既知。連続軌跡全体の精度や未見試合への汎化性能はまだ示していない。

## 処理

元BallTrack重み・閾値0.3・全外側輪郭・外接矩形中心を固定し、対象時点の前後8元フレームを2フレーム間隔で見る。最大9観測、全体で約0.267秒。画像は約59.94fpsで動きの更新は約30fps相当のため、1フレームずつの近い重複をそのまま多重に扱わない。

各時点の複数候補から、候補の強度と前後のつながりを合わせた総コストが小さい経路を動的計画法で選ぶ。出力座標は対象フレームで実際に検出された成分の中心に限定し、線形補間や平滑化で座標を作らない。輪郭の番号を球のIDとして扱わない。

比較した設定は、移動量のコスト又は速度変化相当のコストに、固定した3強度（0.1/0.3/1）を組み合わせた6種類。移動量は64px、速度変化相当の残差は16pxを尺度とし、コストは4で上限を設けた。スコアは未校正のヒートマップ値であり、実球の確率ではない。実空間の速度・加速度の測定でもない。

カメラ切替候補を含む窓、候補の途切れで3観測未満になった区間では元の最大面積方式へ戻す。対象に候補がなければ欠測のままとする。候補なしの区間をまたいで無理につながない。

選ばれた設定は`displacement_0.1`。候補スコアの`-log(peak)`と、`0.1×min(前後2元フレームの移動距離/64,4)`の合計を最小化する。6設定とも学習側の成績が同じだったため、事前の方式順で選んだ。元の正解63件は全て保持し、追加した学習用3例の誤選択を直した。

この方式は未来8元フレーム（約0.133秒）を使うオフライン処理。各ヒートマップ自体もt−3..tの入力を使うため、最大窓ではt−11..t+8の画像を参照する。背景medianとカメラ切替用の特徴も既存クリップから得ている。リアルタイムの因果的な処理とは呼ばず、将来の得点予測等に使う際は参照した未来情報を別途管理する。

## 設定選択と評価の順序

1. 実行前に`protocol.json`へ設定範囲・コスト・選択基準・評価の順序を保存。
2. 既存学習120件＋新規A/C/D3件で設定選択。前回のBはプレー後と確認済みのため含めない。元の学習正解を全保持し、誤出力を増やさない候補から正解数、誤出力数、事前の方式順で選ぶ。
3. `training_selection.json`へ選択設定を固定してから、固定validation120件で元の正解を失わず誤出力を増やさないことを確認。
4. その通過後に4対象を点検。A/Dを保持してB/Cを回復した。
5. その通過後に追加audit60件を元方式と選択済み方式だけで点検。auditで別設定を選ばない。

評価後に強度・閾値・窓幅・コスト式を変える処理は実施していない。

## 変化した対象

- 学習側：003/291、007/851、010/262を誤位置から正解へ。設定選択用であり、評価の改善件数とは分ける。
- validation：015/323を約213.80pxの誤位置から2.00pxへ。
- 4対象：015/328を265.63→1.00px、019/305を222.27→3.00pxへ。元から正しかった012/303・020/171を保持。単一フレームの最大スコアでは012/303を約573px離れた位置へ移していたが、今回の方式はその移動を避けた。
- audit：008/503を325.53→1.41pxへ。

auditの008/503は、以前の人手確認で元の誤った候補を除いた時点でもある。その除外は球不在の確定ではなく、今回の候補は元の手動中心994/252付近の別成分993/251である。将来統合する際も、以前に除外した誤った成分1113/555を復活させてはいけない。今回は正規参照先を更新していない。

## 検証記録

- `training_parameter_comparison.csv`、`training_selection.json`：学習側だけでの設定選択。
- `validation_decision.json`、`challenge_decision.json`、`decision.json`：順次点検と元の正解保持。
- `comparison_summary.csv`、`changed_observations.csv`：用途別の変化。
- `*_component_cache.json`、`*_context_image_hashes.json`：対象時点の全候補と前後入力。
- `post_trial_verification.json`：出力が実際の対象フレーム候補に含まれること、存在/欠測を変えていないことの検査。
- `baseline_reproduction.json`：元方式の120件・60件・4件の存在フラグと座標が既存出力に完全一致。
- `verified_inputs.json`：元注釈・今回の評価注釈・モデル・正規参照先等のハッシュ保持。
- `render_report.json`：動画の復号数・寸法・対象座標照合。

合成系列で動的計画法の結果を全組合せ探索と照合し、カメラ切替・候補なし・短い区間のフォールバックも検査した。正規の追跡出力への統合前には、より長い区間での挙動を比較し、既存の人手訂正を優先して保存する。
