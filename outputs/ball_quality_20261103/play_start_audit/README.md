# プレー開始を先に確定する方針（2026-11-03）

現在の優先順位は、準備中の複数球追跡の拡張ではなく、プレー開始・対象球・解析区間の確定とする。
準備中の2球を追う問題は、主目的であるラリー中の選手配置と得点側の分析に対して優先度が低い。
複数球の診断実験は履歴として残し、その検出数を主ラリーの性能として使わない。

## 解析区間の定義

- サーブ試行の開始候補は、ラケットと球のサービス接触。構え・トスやカメラがコートへ戻る時刻と分ける。
- 主ラリーの位置追跡は、有効サービスの接触以降を対象とする。開始検出用の短い直前文脈と、追跡の評価対象を区別する。
- サービスエースも有効なプレーであり、返球があることを開始の必須条件にしない。
- ファーストフォルトとセカンドサービスは同じポイントの別試行として保持。フォルトを消したり別の得点として数えたりしない。
- ダブルフォルトは主ラリーが成立しないポイントとして別の結果を保持し、都合よくデータから落とさない。
- プレー中に追う対象はサーブで打たれた球。通常1球であっても、検出候補が1個なら正解とする方法にはしない。
- 開始検出のためには直前の構え・トス・動きなども参照する。準備中の全選手・全ての球を高精度に追い続けることを前提にしない。
- 最初から接触を1フレームへ断定せず、未確定なら接触区間とレビュー状態を保持する。

## 既存20クリップの確認

`ball_pilot_start_inventory.csv` で、球追跡パイロットID→既存play_window_id→ラリー候補IDを接続した。
同じ「002」でも、球追跡パイロット002とラリー候補002は異なる。番号の末尾だけで対応させない。

既存クリップの元の開始方法は、20件中13件が `camera_entry_confirmed_not_impact`、7件が `manual_valid_serve_impact` だった。
これは切り出しを作った台帳の開始方法であり、後続の全ての人手レビュー件数を表すものではない。
台帳の切り出し先頭を、そのままサービス接触やプレー開始の正解にできない。

現在の作業フォルダにある細かい開始候補区間を、この20クリップへ確実に結び付けられたのは2件。
ほかに既存の接触時刻だけが残るものもある。古い時刻の小数桁から、接触精度が確定していると解釈しない。
接触時刻がクリップ先頭より前の記録もあるため、開始検出を行うときは切り出し済みクリップだけでなく元動画の文脈が必要になる。

## 元動画の時計

この監査のフレームは、元から注釈・球キャッシュに使われている旧編集版 `match1` の時計である。
再取得版 `match1_original.mp4` やYouTubeの表示時刻に同じフレーム番号を移さない。
既存の比較記録では再取得版との時刻差があり、全動画に適用する確定変換は得られていない。
確認用動画はそれぞれの実際のキャッシュと元クリップを先頭から復号して照合し、JPEG品質95で再圧縮した画素が一致することを確認した。

## 評価の扱い

従来の300標本は準備中も含む可視球検出の診断用データとして残す。
既存テストでの位置再現率75.0%は、プレー中だけを評価した数字ではない。
今後の主評価は、モデルの成否とは独立に開始・終了を区分し、その区間内に固定した標本・連続区間で行う。
失敗した準備中のフレームだけを除いて精度が上がったと報告しない。

## 次の実装順

1. 既存の人手有効性確認と接触候補を使い、少数の区間で開始の定義・時計・試行IDを固定する。
2. サーブ動作・球の発射・必要に応じて音などから開始候補を自動抽出し、正しい開始とフォルト後の構え直しを区別できるか測る。
3. 開始区間の中でサーブに使われた対象球を初期化し、開始後の4選手・球追跡を評価する。
4. ラリー終端の候補と、ポイントの得点側を接続する。カメラ退出やスコア更新時刻を終端そのものにしない。

今回完了したのは既存ラベルの接続・区間定義・044の試行別スコープ出力であり、自動開始検出器はまだ実装していない。
