# 新規手動中心3件の追加学習と候補選択の診断

4件の人手入力を受領した。全行の座標範囲・有限値・ユーザー保存履歴・元画像・元フレーム時計を検査済み。B（006/884）はユーザーの「プレー終了後の球なので賞味追わなくてもよい．」というメモを根拠に、今回の追加学習から除外した。実球中心の注釈は保存し、背景の誤検出や`not_visible`へ変更しない。A/C/Dは可視中心の注釈であり、任意のプレー区分は未入力のため、プレー中と確定してはいない。

## 比較条件

`run_expanded_manual_ball_finetune.py`を1回実行した。既存学習120件にA/C/Dを加えた123件と、学習更新数を揃えた対照を比較した。対照は同じ3クリップの既存可視注釈を各1件、固定乱数で重複配置する。両群は123入力枠、同じ順序、同じ可視/非可視数、各186更新、3epoch。既存難例2件と追加3枠の重み8は以前の方針から固定し、両群で一致させた。重みの再探索は行っていない。

元の重みから各群を初期化し、最終デコーダブロックと予測層のみ学習した。他のパラメータと全BatchNorm統計は凍結し、変更されていないことを検査した。入力はmedian+BGR t−3..t、512×288。元1920×1080の中心から同じGaussian教師を作成。validation120件とaudit60件は固定し、追加3件の入力画像ハッシュとの重複がないことも確認した。

## 結果

以前と同じepoch2・閾値0.3で比較する。「正しい位置」は手動中心から元画像16px以内。「誤出力」は見える球の誤位置と、非可視注釈に対する出力の合計。

| 条件 | 正しい位置 | 誤出力 | 元の正解80件のうち失った件数 |
|---|---:|---:|---:|
| 元モデル | 80 | 3 | 0 |
| 更新数等を揃えた対照 | 85 | 7 | 1 |
| 新しい3中心を追加 | 84 | 7 | 0 |

追加群は対照で誤位置になった014/714を保持した一方、対照で回復した012/667と015/323を回復できなかった。追加注釈の一般的な改善効果は確認できない。

両群の全3epoch×既定5閾値を同じ条件で選択した。「元の正解80件を全て保持し、誤出力を3件以下にする」設定は追加群epoch1・閾値0.4の1件だけだが、正解80・誤出力3で元と同数だった。厳密な改善設定は0件。元モデルを維持し、別の学習済みモデルをauditへ投入する必要はなかった。以前の元モデルaudit結果を参照し、繰り返しのaudit探索を行っていない。

固定120標本には準備中・映像切替等も含まれる。この集計を主プレー中の追跡精度や別試合への汎化性能とは呼ばない。追加3件は学習用に選択した難例であり、評価標本に加えない。

## 検出候補は存在するが、最後の選択で失われる

入力位置の取り違えと、学習後の出力を追加診断した。追加群epoch2で選ばれる最終座標が16px以内になったのはCだけで、A/Dは別の位置を選び続けた。しかし、これは直ちに「実球を検出できていない」ことを意味しない。

元モデルの閾値0.3のヒートマップを全成分に分解すると、**A/C/Dの全てに手動中心の近くの候補が既に存在**した。

| 例 | 元モデルの最も近い候補中心の誤差 | 教師位置から16px以内の最大スコア | 元の最終出力の誤差 |
|---|---:|---:|---:|
| A | 1.18px | 0.309 | 265.38px |
| C | 2.51px | 0.559 | 486.47px |
| D | 1.51px | 0.619 | 557.70px |

ソース`BallTrack/inference.py`の`_predict_location`は、二値化した成分の外接矩形について`w*h`が最大の候補を選択する。面積が大きい別候補を優先した結果、既に存在する実球候補が最終座標から落ちていた。追加学習後も3例全てに実球近傍の候補があるが、A/Dでは別候補が選ばれた。

この3例では候補選択が直接の失敗箇所だと示せる。試合全体の主因、候補の網羅性、別の選択規則の有効性までは示していない。単純に最高スコアへ変更すれば解決するという結論も出していない。次は追加学習や人手注釈を増やす前に、元モデルの候補を保持した上で、候補選択の対照比較を固定したvalidationで行う。主プレー範囲の評価は、境界の確定と分けて整備する。

## 証拠と保存

- `annotation_ingestion.json`、`accepted_center_annotations.csv`：入力の受領・Bの除外根拠。
- `protocol.json`：学習前の固定条件、入力ハッシュ。
- `validation_selection_grid.csv`、`validation_selection.json`、`decision.json`：全設定と元モデル維持の判断。
- `new_training_centers_fit_diagnostic.csv`：追加3件での最終出力。独立な評価ではない。
- `new_center_heatmap_diagnostics.csv`：元モデルと事前に比較点とした追加群epoch2の全成分診断。
- `post_trial_diagnostics.json`：群間の状態変化と追加例の診断。

元300件・今回の生注釈・重み・既存予測・確認済み球/人物/統合版の参照先の保持をハッシュで検査した。正規の追跡出力は更新していない。実行時間は約34秒。診断の結果を使った追加の学習・閾値探索・自動候補訂正は実施していない。
