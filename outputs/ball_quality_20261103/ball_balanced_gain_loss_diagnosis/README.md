# 固定モデルの回復1件・欠測1件の原因分解

2026-11-03。前段 `ball_balanced_fixed_validation` の全変更例2件を対象とした。新たなモデル選択、閾値探索、再学習、注釈追加はない。前段の不採用判断と現行の正規参照を維持する。

| 対象 | 既存手動中心の16px以内の最大応答：元→新 | 全画面の候補成分数：元→新 | 最終出力 |
|---|---:|---:|---|
| A: pilot015/local285、元フレーム104820 | 0.298828 → 0.311035 | 0 → 1 | 欠測 → (1125,594)、中心誤差11.40px |
| B: pilot002/local832、元フレーム15637 | 0.343994 → 0.294189 | 1 → 0 | (800,562)、中心誤差6.32px → 欠測 |

両例とも、実行済みの固定閾値 `>0.3` を応答がまたいだことが、出力の有無を変えた直接の機構である。対象時点には競合候補がなく、候補選択方式を変えても候補自体の消失を回復できない。Bの新モデルの全画面最大値は0.294434で、実球近傍の値とはわずかに異なる。これらはモデルの応答値であり、球である確率や正解確率ではない。

この観察から学習の根本原因を一意に特定することはできない。また「閾値を下げればよい」とも結論しない。特にBは既に結果を確認した監査例であり、Bだけに合わせる閾値や例外の追加は評価への適合になる。新モデルが検証側で1件回復し、監査側で元の正解1件を失った前段の結果は変わらない。既知の別物6候補も解決しておらず、高品質化の達成を主張しない。

## 再現条件と検証

- 元モデルと、前段で固定した差分スナップショット1本だけを比較。元JPEG、median、入力t-3..t、CUDA AMP、各クリップ内の元バッチ4の組を再現した。
- 48モデル・時点出力の成分を以前の保存キャッシュと完全照合。前後9時点×2例×2モデルの36ヒートマップを保存し、別スクリプトで成分と応答36件、対象出力4件を再現した。
- 動画全256表示フレームの復号と1280×800の形状を確認。モデル、注釈、元画像、正規参照、前段結果など保護対象146ファイルの不変を確認した。
- 前後時点の応答測定は「対象時点の手動中心と同じ固定座標」の診断値である。移動する球の正解中心や時系列精度として扱わない。新たな独立精度評価ではなく、同一試合内の既知の開発例の診断である。
