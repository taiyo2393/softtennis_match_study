# 開始候補の整理：人物枠修復と待機文脈（2026-11-03）

**開発用の開始候補整理であり、追跡の自動開始・終了判定には未採用。**
044と002の同一試合2クリップで開発した。今回の002は調整に使っているため、前版のような「条件固定後の別クリップ評価」として報告しない。
元の選手・球の座標、接触注釈、ユーザー確認済みの試行結果は変更していない。

## 実際に修正した問題

前版は奥側の拡大画像を優先してから全景との重複を除いていた。
拡大画像の下端で切れた手前選手の枠が残り、同じ人物の完全な全景枠が重複として消える場合があった。
そのため002では、人物の姿勢が途中までしか見えない枠から接触候補を709–740に置いていた。

切り抜き端4px以内に触れる枠を**重複除去より前**に除き、完全な全景枠を回復した。
016は既存の全景推論キャッシュを再利用、002は同じモデル・画像サイズで全景を再推論しキャッシュへ保存した。
単に検出を削除する処理ではない。修復後の002では、腕上げが702–758まで継続し、音からの候補は745–776となった。
既存AI接触候補747–758と重なるが、独立した接触正解への時刻精度ではない。

## 状態を使った候補の整理

1. 完全な人物枠だけを使い、既存の固定カメラ校正による粗い領域内から手前2人・奥2人を選ぶ。各側の身長相当の枠高が大きい2枠を使う簡易選択であり、本人同定を保証しない。
2. 腕上げで動く枠の中心ではなく、可視の腰関節で短期対応と移動量を求める。直前0.6秒、各人物の身長に対する変位0.2以下などの条件で4人の待機候補を作る。
3. 直前に待機を観測できた場合だけ、人物・姿勢の欠落中も最大1秒間、その古い根拠を保持する。欠落自体を静止とは数えず、観測済みの移動が大きければ解除する。採用候補には根拠のフレームと経過秒数を残す。
4. 腕上げ・音の候補がベースライン付近で出たら開始候補として保持し、それ以降を`activity_or_unresolved`とする。開始候補の接触区間を過ぎた後、4人の静止根拠が連続2秒得られるまで、新しい開始候補を出さない。
5. 根拠不足は保留、活動中の打球は開始候補から抑制する。元候補は全て`phases.json`に残す。

実装した状態は`unknown`、`ready_candidate`、`activity_or_unresolved`の3つ。
**終了、フォルト、再試行、ポイント区切りを自動確定する処理は実装していない。**
再び待機らしい状態になったことは、ポイント終了やファーストフォルトの証明にはならない。
返球を開始の必須条件にせず、エースや短い試行を機械的に除外しない。`outcome`は常にunknown、`point_id`も未付与。
姿勢と音の候補は未来のフレームも参照するオフライン処理であり、リアルタイム開始検出とは主張しない。

## 残る限界と次の比較

- コート内の2人ずつの選択は単純で、審判の混入、選手の交差、ネット付近の枠の揺れ、選手の欠落を誤り得る。固定カメラ校正の流用は粗いROI用で、足元の物理位置測定や接地正解ではない。
- 静止が続くラリーでは誤って待機へ戻り得る。逆に、フォルト後に人物が動き続けると再試行を拾えない。1秒の保持も同じ人物の再取得を証明しない。
- 044の第1試行のように、映像内の直前文脈が短い場合・検出が欠ける場合をまだ救えていない。
- 頭上サーブ以外、放送カット・ズーム、異なる試合・カメラへの適用は未検証。
- 有効性・終了・得点側の自動判断は未実装。既存の確認済み区間での追跡を継続し、この候補整理で注釈を上書きしない。

次は条件を固定し、別クリップに対して同じ候補整理を適用する。
候補の保持／保留／抑制を残したうえで、短いサービス周辺だけ球の発射方向・接触後の飛行を確認する。
接触の独立評価では、開始が映像外／文脈不足の区間も別区分で残し、検出できた試行だけで精度を出さない。
研究の主題は開始検出器そのものではない。少数の別区間でも破綻するなら、確認済み開始区間を入力する半自動方式で選手・球追跡の品質向上を先に進める。

## 保存物と検証

- `phase_protocol.json`：共通パラメータ、コード・モデル入力のハッシュ。全クリップ同じ条件での最終再実行結果。
- 各`protocol.json` / `features.json`：枠修復とラベルを読まない姿勢特徴。
- `match1_motion_pilot_002/full_court_features.json`：回復に使った全景推論。再推論せず再構築できる。
- 各`phases.json`：修復のみの比較、状態条件後の全候補・理由・保持した開始・遷移履歴。
- 各`motion_context.json`：4人の選択枠、欠落状態、移動量。
- `comparison.json`：候補生成後にのみ既存AI接触区間と比較した記録。
- `verification.json`：欠落を静止としない、保持期限、時間経過だけでは解除しない、返球不要、再試行候補と結果ラベルの分離、全景枠の回復を確認する処理上の検証。検出精度の評価ではない。
- `revisions/strict_quiet/`：待機根拠を1秒保持する前の失敗結果。002の本来のサーブ候補を落とし、後の打球を保持していた。
