# サーブ開始候補の最小試作（2026-11-03）

姿勢と音から、サーブ開始の候補をラベルを読まずに出す処理を実装した。
**現段階では自動的にプレー区間を確定する用途へ採用しない。**
開発に使った044では既存2試行の接触区間に候補が重なったが、固定条件で別の002へ適用すると候補過多と時刻のずれが出た。
当面の追跡検証は既存の確認済み開始区間を使い、候補器の出力を確定境界として上書きしない。

## 実装したもの

1. 各クリップ全体を2ソースフレーム間隔で処理。既存YOLO11m-poseでコート全体と奥側の拡大領域から人物・腕の姿勢を取得する。
2. 足元位置の近さで短期の人物軌跡を作り、低移動状態から頭より上へ手首を上げる動作を候補とする。
3. 同じ人物の0.25秒以下の腕上げの途切れをまとめる。
4. 腕上げの始まりから終わりの0.25秒後までの音声のエネルギー立ち上がりを探す。
5. 最大の音の立ち上がりの前後0.25秒を接触候補区間として出力する。

全画面だけの初回版では奥側サーバーを十分に捉えられず、044の候補は0件だった。
奥側の固定拡大領域を加えると候補が3件となったが、第2試行のトスが独立した開始として出た。
同一人物の短い姿勢欠落をまとめる変更で2候補になった。変更前の3候補と条件は `*_before_gesture_merge.json` に保持した。
この開発は044だけで行い、`frozen_detector.json` に条件とコードハッシュを固定してから002へ適用した。

開始ラベル・既存接触区間・フォルト判定を読んで候補時刻を選ぶ処理ではない。
ラベルを読むのは、候補生成後の別の比較スクリプトだけである。
推論は各試行の結果を常にunknownとして出し、フォルト・有効を自動判定したとは扱わない。

## 比較結果

| 区間 | 自動候補数 | 既存接触候補との関係 |
|---|---:|---|
| 球パイロット016＝ラリー候補044（開発用） | 2 | 第1試行105–125に対して97–128、第2試行730–738に対して721–752。両方で区間が重なる |
| 球パイロット002＝ラリー候補007（条件固定後） | 9 | 既存の後続サーブ747–758に対し709–740を提案し、区間が重ならない。途中の打球も候補に混ざる |

044の第1試行フォルト・第2試行有効は既存のユーザー確認から引用した結果であり、今回の自動分類結果ではない。
接触時刻の範囲は既存AI候補なので、この2件の重なりを独立正解に対する検出率100%とは報告しない。
002では初期の試行に関する正解が揃っていないため、既存ラベルと一致しない9候補をそのまま9件の誤検出とは数えない。
ただし後続サーブの候補時刻のずれと、ラリー中の打球も開始候補になることから、開始確定器としては不十分である。
2クリップとも既に見た同一試合の開発データであり、新しい試合での汎化性能評価ではない。

## 分かった限界

- 腕上げと打球音はラリー中の頭上打球にも出る。1人の直前の移動が少ないことだけで、サーブ待機とラリー中を分けられない。
- 最大の音の立ち上がりは接触音とは限らない。声・拍手・バウンドなどを選ぶ可能性があり、音だけで接触を確定しない。
- 奥側の人物では姿勢が欠落・混合しやすい。拡大で改善しても、短期人物IDや手首が正しい保証はない。
- 今回は頭上サーブの動作候補に限定した試作で、アンダーサービスを含めた汎用的な開始判定ではない。
- クリップ先頭がトスの途中の場合は、直前の静止文脈が不足し、候補が出ない場合がある。
- 放送の音と映像の時差を一律補正していない。前後0.25秒は候補幅であり、実測した接触精度ではない。

## 次の改修対象

「サーブ待機→サーブ動作→ラリー中→終了／再試行」という区間の状態を扱い、ラリー中の通常打球を新しい開始として出さない仕組みが必要。
待機判断は一人の腕だけでなく、4選手の移動・構え、サーバー位置、トスから打球までの順序を合わせる。
接触時刻の絞り込みには、候補区間内での球とラケット／打球腕の関係、打球後の球の移動を確認する。
フォルト後の再試行・サービスエース・ダブルフォルトは別の状態として扱い、返球がなければ開始していないというルールにはしない。
次の変更をこの002の結果に合わせて作る場合、それも開発扱いとし、最終評価は新しい固定区間・独立の開始ラベルで行う。

## 保存物

- `frozen_detector.json`：044での開発後、002適用前に固定した候補生成条件とコードハッシュ。
- 各クリップの `protocol.json` / `features.json`：モデル・画像領域・姿勢の全時刻特徴。開始ラベルを使わずに作成。
- `audio16k.wav` / `audio_features.npz`：元クリップ音声と短時間の特徴。
- `proposal_protocol.json` / `proposals.json`：条件・全候補・人物動作・音の根拠。
- `comparison.json`：候補生成後に既存ラベルと照合した結果。
- `match1_motion_pilot_016/automatic_start_candidates_h264.mp4`：044の2候補を0.5倍速で表示。右は自動検出した人物周辺の等比2倍表示。フォルト・有効をAIが判定した表示は入れない。
- `match1_motion_pilot_002/timing_failure_h264.mp4`：002の時刻ずれの例。橙枠は自動候補709–740、水色枠は既存AI接触候補747–758。水色を独立した正確な接触正解とは扱わない。
- `verification.json`：欠落手首を腕上げとしないこと、短い途切れの統合、002への同じ条件・コード適用、元レビュー表の不変を検査。
- 両動画の全フレーム復号を確認済み。これは開始検出の精度評価ではない。
