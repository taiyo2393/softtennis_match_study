# 追加学習なしの一般球検出モデルによる候補確認

既存のローカルYOLO11m重みのCOCO `sports ball` クラスを、同じ36確認候補の96×96pxパッチへ適用した。
推論前に`protocol.json`へimgsz640、confidence0.10、NMS0.7、元画素で候補中心から8px以内という条件を固定した。
検出器の学習や閾値探索・再実行は行っていない。

| 対象 | 近傍の球検出あり / 確認候補数 |
|---|---:|
| 実球 | 2/21 |
| 誤検出 | 0/15 |

誤検出候補で反応しない一方、実球19例を落とすため、既存候補を自動除外するフィルタには不採用。
「球検出なし」を「実球なし」と解釈してはならない。この結果を高精度な球追跡と表現しない。
成功は773/784の2候補であり、候補のスケールや場面が異なる場合も含めた今回の設定では適用範囲が足りない。
設定やスケールを変えた一般検出器全体が不可能という結論ではないが、ここで対象例に合わせて条件を繰り返し調整しない。

`predictions.csv`・`sports_ball_boxes.csv`に位置・距離・検出スコアを、`decision.json`に判断を保存した。
全例が選択した同一試合内の既確認候補なので、実球の正確な中心座標や全フレームの独立精度は測っていない。
正規の追跡入力・レジストリ・元注釈・重みのハッシュを保持した。
