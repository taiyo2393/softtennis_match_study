# 元の検出を保持した欠落補完：予備比較

## 判断

追加学習モデルを元モデルへ全面置換せず、元が欠測の時刻だけ追加する方式を比較した。
設定選択用120標本では、正しい検出を4件増やし、元の正しい80件を全て保持した。
一方、ラケット付近への誤位置を1件追加し、誤位置・誤出力が3→4件となるため、自動補完には採用しない。

| 条件 | 正しい位置 /105可視標本 | 誤位置・誤出力 | 追加した出力 |
|---|---:|---:|---:|
| 元モデル | 80 | 3 | 0 |
| 補完threshold0.3 | 84 | 4 | 5 |
| 補完threshold0.4 | 83 | 4 | 4 |
| 補完threshold0.5 | 81 | 4 | 2 |
| 補完threshold0.6/0.7 | 80 | 3 | 0 |

元の正解標本を保持し、誤出力数を元以下にするという事前条件を満たす改善設定はなかった。
この判断は今回固定した保守的な運用条件によるもので、4件回復・1件誤位置という交換関係そのものを隠さない。

## 方法

元モデルがvisibleの行は座標・強度・有無をそのまま残す。
元が欠測の場合のみ、追加学習済みepoch2の同じフレームの実際の検出を候補にする。
前後に元モデルの検出があり、欠測の連続長8フレーム以下、前後を結ぶ線形参照から16px以内、既存の画面切り替え候補に重ならない場合だけ補完候補として出す。
線形参照は選択の制約だけに使用し、出力位置は検出器がそのフレームで出した座標。補間はしない。
候補選択処理に手動座標は渡さず、選択後に既存手動中心と照合した。
条件と5つの閾値を`protocol.json`へ実行前に保存。既に見たデータに対する開発比較であり独立評価ではない。

## 残った1件と追加点検

019の325フレームでは、手動中心が(968,669)、補完候補が(1106,605)で、ラケット付近への誤位置となる。
元モデルの直前324も(1106,586)、直後326も(1106,607)で、補完候補は線形参照から8.5px以内。
**前後の支え自体が誤位置だと、二つのモデルと時系列の一致だけでは誤検出を識別できない。**
検出強度も正しい補完例の前後アンカーと同程度であり、支えがあることを実球の証拠にはしない。

`body_aware/`に追加候補の中心が人物・ラケット矩形へ重なれば補完を保留する一度だけの比較を保存した。
固定YOLO11m、imgsz1920、confidence0.25、classes person/tennis racket、矩形拡張なし。
019/325ではラケットを検出できず、候補中心も人物矩形の外にあり、この5候補の結果は改善しなかった。
身体への重なりは実球でも起きるため、元の観測の除外には使わない。
この後に矩形を広げたり、当該失敗だけに合わせた閾値調整はしていない。

## 保存と次の段階

`selection.json`、`validation_decisions.csv`、各閾値のCSV、`body_aware/selection.json`に不採用設定も含め保存。
`continuous_diagnostic_proposals.csv`は診断用提案で、運用中の観測として登録していない。
動画460フレームの全復号、対象5点の保存済み推論との位置差2px以内、元観測の保持・補間なし・元注釈とレジストリのハッシュ不変を検査した。
設定選択側で採用できなかったため、後段60標本で採用を再選択していない。選択された運用は元モデルのまま。

次に向け、`../balltrack_manual_finetune_pilot/training_hard_cases/`へ、学習側120標本だけから目標中心と64px超離れる既存検出2件を整理した。
「注釈対象の位置として誤り」というラベルで、別の実球が存在しないとは断定していない。
この2件を含む難例の学習側整備を優先し、既知の設定選択例へ条件を足し続けない。
