# 新規補完候補だけへの人物・ラケット重なり保留

時系列の支えがあっても019/325のラケット候補が残ったため、設定選択側の失敗を見た開発上の追加点検として実行した。
条件を`protocol.json`に先に保存し、固定YOLO11mのperson/tennis racket矩形に新規候補中心が含まれれば、その補完だけを保留する。
元の検出は一つも消さず、重なりを実球でないというラベルへ変換しない。

5つの補完候補フレームでは、この条件による追加保留はなく、結果は前段と同じ。
失敗019/325でラケットの矩形は得られず、新規候補も人物矩形から外れていた。
矩形の拡張や検出閾値の再調整はせず、自動補完への採用は見送った。

`validation_object_boxes.json`に検出矩形、`validation_decisions.csv`に重なり判定、`selection.json`に全条件の結果を保存。
この結果は汎用のラケット検出器全体の性能評価ではなく、今回固定した候補保留条件の失敗記録である。
