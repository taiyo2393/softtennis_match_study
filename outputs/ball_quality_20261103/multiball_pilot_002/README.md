# 複数球候補を保持する追跡の試作

**優先順位の変更：この実験は準備中の診断用として保存し、拡張を進めない。**
ユーザーの指摘に基づき、先にプレー開始を判定し、開始以降の追跡を主対象とする。
既存ラベルの接続と開始区間の定義は `../play_start_audit/README.md` を参照。

002の局所軌跡を調べると、本物の球を外れ値扱いしたときの基準も、別の選手がつく別の実球だった。
014では線審の頭付近への誤検出が基準だった。二つは異なる失敗であり、同じ距離閾値の調整では解決しない。
この試作では候補を一つに絞る前のモデル出力を残し、初期位置で選んだ球ごとに別々の追跡候補を作った。

## ユーザー確認の範囲

- 002・318：候補が実際の球であると確認済み。中心画素の精密な注釈ではない。
- 今回の動画に対する回答「球が二球ある」：場面に2球あるという確認として保存した。
- 上の回答を、緑の軌跡全体の正解・ID維持・全座標の正確さ・次にサーブされる球の確定とは扱わない。
- `user_two_ball_review.json` に質問・回答とこの解釈を記録した。

## 変えた部分

1. 元と同じMS-TrackNetV3・重み・背景中央値・入力時刻で、002の280–360フレームを再推論した。
2. 従来の1候補出力を再現できることを全81フレームで照合した（座標差2px以内）。
3. 既存の弱候補抽出と同じ閾値0.10で、連結領域をフレームあたり最大6個残した。順位は各フレームの順であり固定IDではない。
4. Aはユーザーが球と確認した318の元モデル座標(558,680)を起点にする。対応する成分の座標はモデルの重み付き重心であり、精度が向上したという意味ではない。
5. Bは310でAから離れたもう一つの強い成分をモデル側で選び、別の追跡候補にする。Bの画素位置をユーザーが指定したわけではない。
6. 直近位置からの距離32+8×欠落フレーム数px以内の成分を対応付ける。欠落8フレームを超えたら停止し、近い2候補の差が8px未満なら割り当てを保留する。
7. A・Bに同じ成分が割り当てられた場合は両方を保留し、一方を恣意的に優先しない。

元の候補の中から選ぶ処理であり、欠落時刻の座標を補間・外挿して出力しない。
原モデルと他方の候補は保存し、選択対象でないという理由で誤検出とは決めない。

Aの16候補のうち、従来の単一出力と16px以内で一致したのは1フレームのみだった。
残る候補は元のヒートマップに存在していても、単一候補への絞り込みで失われていた。
これは候補取得の改善を示すもので、独立正解に対する15件の精度改善を示すものではない。

## 限界と次の課題

この区間を既に見てから作った初期位置付きの開発例で、完全自動追跡や独立テストではない。
特にAは16/81フレームに候補があるだけで、途切れは多い。複数候補を残すだけで未検出が回復したとは言えない。
2球が近づく・重なる場面や、他の服装・背景・試合で同じ球を維持できるかは未検証。

ラリー分析では、準備中の複数球とサーブに使われた対象球を分ける。
実球が2個ある状態を一方の「誤検出」や「非可視」に置き換えず、対象不明は別の状態として残す。
次は選手のサーブ接触と球候補の対応、または対象球の明示的な初期化によって対象を決め、その球を失った場合は別の球へ勝手に切り替えない処理が必要となる。
新しい候補数や人手の初期化を、本人同定精度・位置精度の向上と混同しない。
