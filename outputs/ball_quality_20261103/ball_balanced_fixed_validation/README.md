# 学習側で固定した毎バッチ学習モデルの開発検証：監査で不採用

学習側では正しい位置66件を全て保ち誤出力4→2となり、固定した別クリップの評価120時点でも81→82正解・誤出力2維持となった。しかし監査60時点で元の正しい球位置を1件落とし、35→34正解となった。既知の非ボール6候補の近傍にも出力が残るため、元の正規モデルと人手訂正を維持する。

## 診断から別の固定検証へ

前の2×2実験と位置診断は学習側だけで完了し、評価への適用や実用モデルの選択は行わなかった。本フォルダはその後に新しく条件を固定した開発検証であり、前のプロトコルを後から変更したものではない。

学習側の厳密改善候補を、正解最大・誤出力最小、同点は保持あり・小さい閾値の順で比較し、`balanced_preserve`・閾値0.3を1つだけ固定した。診断用差分をバイト単位で一致する`candidate_frozen_delta.pth`へ保存し、学習条件・153更新・元の重みへのSHA256を記録した。元ファイルの`diagnostic_only`メタデータも変更していない。この新しい検証候補としての役割は`frozen_selection.json`と新しい`protocol.json`で明示した。

モデルの再学習、epochや閾値の追加選択はない。既存のdisplacement0.1、入力時計、median+BGR t−3..t、512×288、CUDA AMPをそのまま使う。評価に失敗した後に保持なしモデルや別の閾値へ切り替えない。

## 比較の順序と結果

学習8クリップと別のクリップを使うが、全て同じ試合・繰り返し見た開発データである。独立した未見試合テストとは呼ばない。

評価120時点で元の正解を失わず誤出力を増やさない場合だけ、プレー確認済み4challengeと短区間26へ進む。両方も維持し、評価で改善又は既知の誤候補の出力なしがある場合だけ、選択済み1候補で監査60へ進む。非ボール6候補は成績によらず別の診断として実施することを先に固定した。

## 変化した正解/欠測

- 評価015/285、元フレーム104820：元は欠測、新モデルは(1125,594)。手動中心(1118,603)から約11.4pxで、16px基準を満たした。
- 監査002/832、元フレーム15637：元は(800,562)で手動中心(806,564)から約6.3px、新モデルは欠測となった。

これは実球の物理的消失ではなく、観測位置の出力がなくなった失敗である。監査002/832に合わせて閾値を下げたり、元モデルでその1点だけを補ったりはしない。

4challengeと短区間26の微小な平均誤差の差は、手動中心の精度・共有標本・既知の開発データという限界を持つ。0.1〜0.2px程度の差を独立した精度改善として強調しない。

## 040の人手否定6候補

手動除外後の欠測CSVではなく、元画像から再推論した。463/464/465/467/470/554の全6時点で、否定済み座標から16px以内に出力が残った。座標がわずかに変化した新しい出力の物体同定や、真の球中心・可視性は新たに確認していない。このため「6誤検出を回復/除去できた」とは扱わない。既存の6件の人手訂正を保持する。
