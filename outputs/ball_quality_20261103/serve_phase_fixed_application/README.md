# 固定した開始候補器の別区間への適用（2026-11-03）

**003・008の両方で、開始として保持できる候補は0件だった。現方式を追跡の自動開始条件には採用しない。**
開始候補器の閾値追加はここで保留し、既存の確認済み試行結果と接触候補を使える区間から追跡品質の改善へ戻る。
候補が出なかったクリップを評価対象から削除したり、「サーブやラリーが存在しない」と扱ったりしない。

## 適用前に固定したこと

- 前回の`serve_phase_pilot_v3/frozen_development_protocol.json`に保存したコード・パラメータ・校正をハッシュで照合。
- 姿勢モデル、画像領域、2フレーム間隔、端の不完全枠除去、重複除去、腰による対応、待機と活動の条件を維持。
- 003と008を出力生成前に`application_plan.json`へ指定。003は次の未適用クリップ、008は先頭近くに既存接触時刻があるクリップとして選んだ。
- 推論は開始ラベル、有効性ラベル、既存接触時刻を読まない。照合は生成後の別スクリプトで行った。
- 新しい一括特徴抽出の実装は、開発区間016・002の計4フレームで、保存済み修復後特徴と人数・枠・姿勢が0.05px許容内で一致することを確認した。これはソフトウェアの整合確認であり、検出精度ではない。

これらは以前に追跡等で見た同一試合の映像であり、外部試合の独立評価ではない。
今回の結果に合わせた閾値変更・入力の前後拡張は行っていない。

全候補と保留理由は各`phases.json`に保存した。

### 003

腕上げはlocal98–170、音を使った接触候補は155–186。
直前local96では選択できた候補が手前2・奥1で、4人分の待機を確定できず保留となった。
「検出できた枠が4個」と「本人を正しく4人追跡できた」は区別する。途中で4枠あっても、全員の継続した移動根拠が揃うとは限らない。
独立した正確な接触区間は現在の台帳にないので、155–186を新しい正解注釈へ昇格させていない。

### 008

既存台帳の接触時刻1042.318483秒は、切り出し開始1042.0秒から約0.318秒、local約19.1。
先頭の画像ですでに腕を上げたサーブ動作が進んでおり、候補器が必要とする事前の人物・姿勢文脈を十分に取れない。
最初の接触付近には動作候補が出ず、後半の3候補も開始として保持されなかった。
この台帳時刻は既存の接触記録であって、今回の独立したフレーム精度の正解ではない。有効性の人手確認とも混同しない。
4人分の待機条件、クリップ先頭で途中から始まる動作、人物選択・姿勢欠落が、それぞれ障害となる。
文脈を拡張すれば改善する可能性はあるが、今回それを実測したとは主張しない。

## 研究上の判断

開発した002で候補が減ったことだけでは、自動開始条件としての有用性を示せなかった。
少なくとも、追跡を必要とするこれら2区間を入口で止めるため、現方式を主処理に入れる根拠はない。
これは全手法の自動開始検出が不可能という結論ではなく、この固定した姿勢・静止・音の条件の不採用判断である。
独立正解が揃っていないため、適合率・再現率・開始時刻誤差を数字として報告しない。

次の追跡作業では`tracking_entry_routes.json`に従い、既存根拠を使う。

- 044／球016：第2試行有効は既存ユーザー確認、接触local730–738と終端はAI候補。既存の保守的な主プレー候補区間739–1140を用いる。これは独立した境界・座標正解ではない。
- 008／ラリー026：既存接触時刻は追跡初期化の試作入力としてのみ利用可能。有効性と詳細境界が未確定のため、確定した主評価ラリーにはしない。
- 003／ラリー010：今回の接触候補は短い映像確認用として保持。既存の確認済み開始として扱わない。

自動候補器の成否とは独立して試行結果・接触区間・終端・対象球の根拠を保存する。
研究の主題である選手配置と得点側の関係の分析へ進むには、これらとは別に選手ID・位置精度と得点側ラベルが必要。
