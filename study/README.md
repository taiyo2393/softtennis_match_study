# 固定主カメラのソフトテニスダブルス映像における前衛動作と相手後衛打球方向の観察分析

現行の研究目的は、固定主カメラの試合映像から、**手前コートの対象前衛の相手後衛インパクト前0.5秒間の2D動作特徴と、相手後衛の実打球方向との統計的関係**を検討することである。

単位は、奥コートの相手後衛が打球し、その打球が手前コートの対象前衛の左側または右側を通る1インパクトである。目的変数は対象前衛視点で人手確認した `front_left` / `front_right`、説明変数は打球前の対象前衛の横位置・横移動量である。これは観察映像に基づく関連の分析であり、前衛動作が打球方向を因果的に変えたことは主張しない。

既存の定点カメラ選別・人物候補追跡・Pose推定・人手監査は、研究用データを半自動で作成する前処理として使う。AI候補が出ること、検出率が高いこと、あるいは少数のラベルとの一致だけをもって、手法の有効性や一般化可能性とはしない。

## 現在のパイロットの位置づけ

`match1` の無作為30候補では、方向ラベルが確定した11件のうち、人物追跡・足首Poseの監査まで通過したものは10件（`front_left`: 7、`front_right`: 3）である。これは処理連鎖の実現可能性を示す予備結果であり、予測精度、群間差、方向との関連を結論するための標本ではない。

主解析に進む前に、同じ固定カメラ様式の**複数試合**から、少なくとも左右各30件、可能なら各50件以上の利用可能イベントを確保する。評価時には試合または選手組をまたぐ分割を用い、同じラリー由来のイベントを学習用・評価用へ混在させない。

## 運用原則

- `data/raw/` の4K60元動画は上書き・再圧縮・Git管理しない。
- 動画を物理的に切らない。カット・リプレイの判定は `data/segments/main_camera_segments.csv` に保存する。
- AIの生出力は `data/tracking/` と `data/pose/`、人手の修正は `annotations/corrections.csv` に分離する。
- ボール候補生成は RacketVision の MS-TrackNetV3 を用いる。ただし、画面座標の軌跡だけを対象前衛視点の最終方向ラベルとして自動確定しない。
- 必須の人手ラベルは相手後衛のインパクトフレームと、対象前衛視点の実打球方向である。AIの人物追跡・Pose・ボール候補は、低信頼箇所を監査するための補助情報として保存する。
- 解析に使わない試技も `annotations/exclusion_log.csv` に理由を残す。
- 第三者映像は、保存・フレーム抽出・Pose解析・発表掲載について権利者の許諾を確認してから本解析に用いる。

## IDの関係

`video_id -> segment_id -> rally_id -> trial_id -> frame / player_track_id`

時刻は原動画の `timestamp_sec` を正とする。proxy動画や切抜きのローカルフレーム番号だけでは管理しない。

`segment_id` は定点画角区間であり、試技ではない。ラリー境界を確認して完全な `rally_id` を定義するまで、区間断片を `trial_id` として登録しない。

## 処理の順序

1. 動画情報を `data/metadata/videos.csv` に記録する。
2. 低解像度proxyでカット・主カメラ区間を検出し、`data/segments/` に保存する。
3. 主カメラ区間で人物追跡を実行する。
4. 相手後衛のインパクトフレームを人手で確定し、固定主カメラ・完全なラリー区間に含まれる候補だけを残す。
5. 対象前衛視点の実打球方向を、人手で `front_left` / `front_right` / `uncertain` / `excluded` と監査する。
6. 採用イベントだけ、元4K60から手前コートの対象前衛を追跡し、足首中点に基づく打球前0.5秒間の2D横位置・横移動量を抽出する。
7. 方向ラベルと動作特徴を結合し、初期位置・打者位置・局面・試合を統制可能な範囲で記録する。
8. 十分な複数試合データが得られた場合に限り、単純な基準モデルと正則化ロジスティック回帰を比較し、試合単位で評価する。
