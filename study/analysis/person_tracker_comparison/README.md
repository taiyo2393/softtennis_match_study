# 4選手追跡の予備比較（match1）

2026-09-26。4K 59.94fps の元映像から、主カメラの3区間を全フレームで処理した。YOLO11m の人物検出に ByteTrack または BoT-SORT（`with_reid=true, model=auto`）を接続した。後者の外観特徴は検出器内部の特徴であり、選手専用の再識別モデルを別途学習したわけではない。骨格推定は使っていない。

| 区間 | 元動画フレーム | 解析可能な主カメラ内 | ByteTrackで4選手を選んだ後の観測枠 | BoT-SORTで4選手を選んだ後の観測枠 |
|---|---:|---:|---:|---:|
| pilot_003 | 428–607 | 428–539 | 444/448 | 446/448 |
| pilot_004 | 2471–2650 | 2471–2577 | 414/428 | 410/428 |
| pilot_005 | 4301–4480 | 4301–4480 | 715/720 | 715/720 |
| 合計 | 540フレームを処理 | 399フレームを選択 | 1573/1596 | 1571/1596 |

「観測枠」は、4選手×フレームのうち追跡候補の箱が出た数。**人物同定の正解率ではない**。主カメラ区間は既存の `analysis_ready_main_camera_segments.csv` で制限した。区間の先頭では、足元の上下位置とコート領域から各側2人を自動選択し、その後はコートの外へ走っても対象から外さない。初期選択は3区間の先頭画像で目視確認した。手前・奥の役割割当てはこの映像の画角に合わせた暫定規則であり、チェンジコートをまたぐ選手本人の同定を保証しない。

既存の人手監査済み「奥側前衛」軌跡（3事例×43フレーム）と候補枠を比較すると、IoU 0.5以上は両方式とも129/129フレーム、いずれも各事例内で同一IDに対応した。参照枠は同じYOLO11m系列の検出結果を人が監査したもので、独立に描画された正解枠ではない。したがって、この数値だけで追跡手法の一般的な精度差は結論できない。

ID切替への対処は、終了した軌跡の箱と、新しく現れた箱の位置・大きさが連続する場合に限る。F519のBoT-SORTのID4→19は同フレームに重なった検出から連結した。F4380–4384では奥側前衛が近くの選手と重なり、F4385で新IDとして現れたため、前後の足元位置・箱サイズから暫定的に連結した。後者は要確認と記録してある。検出のないフレームを補間して「観測済み」とは扱っていない。

ByteTrackを次の拡張実験の暫定標準とする。3区間では観測枠が僅かに多く、明瞭なID切替も少なかった。しかし差は小さく、どちらが優れているかを示す評価ではない。視認可能な4選手の正解箱と本人IDを、異なるラリー・試合から別途標本抽出して比較する必要がある。

## 追加区間と打球直前の可用性（2026-09-26）

欠落の多かった3区間でBoT-SORT（`with_reid=true, model=auto`）も実行した。観測枠はpilot_007で608/720（ByteTrackは619）、pilot_012で704/720（同606）、pilot_013で701/720（同575）。区間によって増減が逆転する。後から区間ごとに良い方式を選べば評価は楽観的になるため、方式選択規則を事前に固定するまでは研究結果に混用しない。外観情報を使えば常に改善する、とは言えない。

次はラリー単位で標本を固定し、開始・終了と得点側を確認した上で、各ラリーの同時4人可用率、ID切替、独立した目視正解に対する位置誤差を評価する。入力映像を得点が決まる前で切る評価設計も必要。枠出現率だけを「正確に追えた割合」と呼ばない。

## 速度による軌跡再連結の試作

`scripts/100_reconnect_four_player_tracklets.py` は、選択済みIDが途切れた**末尾**から、未使用の新IDの先頭へ、両端5観測の足元位置・速度・箱の高さを使って候補を出す。最大30フレームの空白で、前向き・後向き予測の両方が箱の高さ0.75以内、箱の高さ比0.6～1.6、競合候補との差が0.25以上の場合のみ暫定連結する。12フレーム以下の空白だけ両端位置を線形補間する。閾値は予備実装の安全側の設定で、正解データに対する最適化はしていない。中間欠損、連続する複数のID切替、長い遮蔽は現在の対象外。

7区間に適用すると暫定連結は2件：pilot_011 の奥側後衛ID 5→158（欠損7フレーム）、pilot_013 の奥側後衛ID 10→22（欠損1フレーム）。他の5区間では条件を満たす連結候補がなかった。4枠同時に出現するフレームは、pilot_011で143→163/180、pilot_013で35→168/180となった。これは連結したIDを本人と仮定した*候補枠数*であり、人物同定精度の改善を意味しない。さらに位置補間を加えると170/180、169/180になるが、補間値は観測値ではない。

出力は各pilotの `bytetrack_four_player_reconnection.csv` と `.json`。CSVの `position_source` は `observed`（元の観測）、`observed_relinked`（暫定ID連結）、`interpolated`（非観測の推定位置）を区別する。`observed_relinked` と `interpolated` はいずれも `requires_identity_review` を付けており、得点分析にそのまま投入しない。元の追跡・ラベルCSVは変更していない。次はこの2件の全再連結区間で本人IDを目視検証し、閾値と誤連結率を評価する。

利用するファイル：各 `pilot_00*` フォルダ内の `bytetrack_selected_four.mp4`、`bytetrack_selected_four.csv`、`four_player_selection_summary.json`。確認が必要な3箇所だけを `bytetrack_review_queue.csv` と短い動画にまとめた。元の研究用ラベル・追跡CSVは変更していない。
