# ボール候補生成の比較・評価計画

## 位置づけ

この処理は、ソフトテニス映像からボール候補を提示し、人が不足・低信頼箇所だけを確認するためのものです。候補が描画される割合を「検出精度」や「打球インパクト検出精度」と呼んではいけません。

現行の実装は RacketVision の公開 BallTrack 重みを用いる **MS-TrackNetV3** です。入力は連続4フレームと、同一クリップから計算した静的背景の中央値です。したがって、これは既に TrackNetV3 系の比較基準であり、YOLO の物体検出器ではありません。

## 実施済みの設定差確認（予備クリップ1本）

対象は `match1_motion_pilot_001`（480フレーム、60 fps）です。出力は [`analysis/balltrack_ablation/match1_match1_motion_pilot_001_candidate_summary.csv`](../analysis/balltrack_ablation/match1_match1_motion_pilot_001_candidate_summary.csv) に保存しています。

| 条件 | 候補フレーム数 / 480 |
| --- | ---: |
| 閾値 0.30、中央値120フレーム | 315 |
| 閾値 0.40、中央値120フレーム | 296 |
| 閾値 0.50、中央値120フレーム | 271 |
| 閾値 0.60、中央値120フレーム | 180 |
| 閾値 0.70、中央値120フレーム | 28 |
| 閾値 0.50、中央値30フレーム | 271 |
| 閾値 0.50、中央値480フレーム | 270 |
| 閾値 0.50、最初の1フレームを静的背景として使用 | 256 |

この1クリップでは、中央値を30枚から全480枚に増やしても候補数はほぼ変わりません。最初の1フレームへ置換すると256候補へ減りましたが、公開重みは中央値背景を前提に学習されているため、これは背景なしモデルとの公平な比較ではなく診断値です。一方で閾値を下げれば候補は増えますが、増えた候補が真のボールである保証はありません。よって、候補数最大の閾値を採用してはならず、閾値は下記の正解ラベル付き検証集合で固定します。

## 比較の成立条件

各手法を同一の固定主カメラ区間、同一フレーム、同一の正解位置で評価する。閾値などの選択は検証集合のみで実施し、選択後の設定を未使用のテスト集合で1回だけ評価する。フレームを無作為に分けず、ラリー単位（可能なら試合単位）で分離する。

最低限の評価値は次の通りです。

- 可視と手作業で確認できたフレームでの Precision、Recall、F1
- 真のボールを出したフレームでの中心位置誤差（px とコート幅で正規化した値）
- 打球インパクト候補の再現率と誤検出数（正解インパクトから ±1 フレームを一致とする）
- 人手修正が必要だったフレーム率、および1ラリー当たりの確認時間

「目視でほぼ追える」は開発上は重要な観察ですが、研究の性能評価には使えません。最初の評価用正解ラベルは、少なくとも独立した5ラリー以上から時間層化して300フレーム程度を抽出し、ボール中心または `not_visible` を手作業で付けます。打球インパクトは別途、映像を正とし音声は補助に限定します。

## 現在の評価セット

`match1` の20クリップに現行モデルを実行し、各クリップから時間的に均等な15フレーム、計300フレームを固定した。ラベルファイルは `annotations/balltrack_groundtruth_match1_pilot.csv` である。候補の前半10クリップ（150フレーム）は閾値・後処理を固定するための validation、後半10クリップ（150フレーム）は設定を触らない最終 test とする。

正解付与時には候補位置と信頼度を非表示にしなければならない。`scripts/39_review_balltrack_groundtruth_server.py` の画面は原画像と前後2フレームだけを表示する。評価フレームで可視なら中心をクリックし、不可視なら `not_visible`、判定不能なら `uncertain` を記録する。前後フレームは可視性の確認にのみ使い、座標は評価対象フレームに限る。

## TrackNetV3 から V6 の扱い

### TrackNetV3

現行手法は RacketVision の MS-TrackNetV3 なので、単に「TrackNetV3を使った」と表現するのは正しいです。ただし、元の TrackNetV3 と公平に優劣比較するには、同じ種類の事前学習済み重み、同じ入力解像度、同じ後処理を用意する必要があります。公開された別競技（主にバドミントン）の重みをそのまま追加し、ソフトテニスでの優劣を主張する比較はドメイン差が大きく、不適切です。

### TrackNetV4

2026-09-11 に公式実装 `TrackNetV4/TrackNetV4` を `third_party/TrackNetV4` へ取得した。MITライセンスのTensorFlow実装で、3フレーム入力の TrackNetV4 Type A / Type B を含む。しかし、リポジトリ内に `.keras` 重みはなく、`docs/RESULT.md` の全ての Download リンクは `#`（実体なし）だった。公式プロジェクトサイトはデータセットの申請フォームだけを示し、重み配布先を示していない。

そのため、**現時点では実動画でのTrackNetV4推論・比較はできない**。未公開の重みを補うために自前で学習するには、ソフトテニスのフレーム位置ラベルと学習・検証・テストのラリー分割が新たに必要となり、今回の半自動アノテーション支援の評価とは別研究になる。著者から正式なテニス用重みを入手できた場合だけ、同一の固定テスト集合で追加比較する。

### TrackNetV5

公式SDKは V2 / V4 / V5 の推論コードを含むが、V5重みと学習データは企業のプロプライエタリ資産として非公開である。SDKのソースだけでの推論は不可能であり、自前学習もV4と同じ理由で本研究のスコープ外とする。

### TrackNetV6

2026-09-11 に公式リポジトリ `Gi-gigi/TrackNetV6` を取得し、README・デモ・配布物を確認した。README は学習済み重みの存在を記載している一方、取得したリビジョン `9a6e4b0443abe11edb52cf3a0297f49dafc17f11` には `models/TrackNetBeta.pt` が含まれず、デモは固定パスを前提としている。完全な推論パイプラインも未公開と明記されている。この状態でランダム初期化モデルを動かしても比較にはならないため、**本研究では TrackNetV6 を実行結果に含めない**。

将来、著者が重み・推論手順・ライセンスを公開した場合のみ、上の固定テスト集合で追加比較する。最新版であることは採用理由にならず、同一データで再現可能に評価できることが採用条件である。
