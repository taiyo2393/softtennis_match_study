# 動作予測イベントのアノテーション手引き

この手引きは [motion_prediction_plan.md](motion_prediction_plan.md) の主解析用である。既存のサーブ・ラリー境界監査と混ぜない。

## 1. 何を1イベントとするか

1イベントは、相手後衛がベースライン付近から打つグラウンドストローク1回である。サーブ、サーブフォルト、ボレー、ロブは主解析のイベントにしない。

`t=0` は**相手後衛打者のラケットとボールが接触した原動画フレーム**である。「サーブ動作開始」や打球音が鳴った時刻ではない。音声は候補確認の補助に留め、映像上の接触フレームで最終決定する。

## 2. 対象前衛

対象前衛は、`t=0` に打者の相手チームでネット側にいる選手である。固定主カメラの通常画角では、原則として**手前コートのネット側選手**が対象になる。ただし、実際のチーム配置・打者位置で必ず確認し、画面上の手前／奥だけで機械的に決めない。

## 3. 入力と予測対象の時間窓

動画の実fpsを `fps`、インパクト原動画フレームを `F0` とする。

- 入力：`F0-round(0.5*fps)` から `F0` まで
- 予測対象：`F0+round(0.1*fps)`、`F0+round(0.2*fps)`、`F0+round(0.3*fps)`

入力データに `F0` より後のフレームを含めない。Poseの前後平滑化も、未来フレームを使う方式は主評価では使わない。

## 4. 採否

採用にするには、入力窓と最長予測時点（`+0.3秒`）の間、固定主カメラが連続し、対象前衛を同定でき、横位置を取れる必要がある。

次の場合は `excluded` とし、推測して埋めない。

- 打球接触フレームが判定不能
- 対象前衛・打者・チーム対応が曖昧
- 対象前衛の足部・骨盤が大きく遮蔽される、またはPose/追跡IDが破綻
- カメラ切替、リプレイ、著しいズーム、残像、コート基準の消失
- サーブ、フォルト、ボレー、ロブ、打者が後衛条件を満たさない

短いPose欠測を補間する規則は、20イベントの予備調査後に固定する。規則確定前は `needs_review` とする。

## 5. 記録の順序

1. 定点主カメラの連続性を確認する。
2. 打者・対象前衛を人物IDで記録する。
3. `F0` を映像で確定する。
4. 入力窓と `+0.3秒` までの可視性を確認する。
5. `included`、`excluded`、`needs_review` のいずれかを記録する。
6. Pose取得後に、正規化横座標と `Δx` を別CSVへ生成する。

左右・静止ラベルを先に主観で付けない。連続値の `Δx` から二次的に作る。

## 6. 信頼性確認

全体の10〜20イベントを無作為抽出し、別日にもう一度アノテーションする。少なくとも、インパクトフレーム差、打者・対象前衛同定、採否、除外理由を比較する。ここで不安定な項目は、モデルの説明変数・目的変数に使わない。
